### 🔴 정정 체인에서 결함 하나를 잡았다

첫 구현은 `exchange_records` 의 **`related`** 로 원공시를 찾았다. 그 필드는
**정정 체인이 아니라 관련공시 묶음**이다 — 같은 회사의 서로 다른 사업이 서로를 가리킨다.
결과:

```
삼성E&A  883,888,500,000 → 1,770,780,000,000     ← 🔴 없는 금액 변화
  정정본  [P4 Ph2(하동)] 그린동 변전소
  "원공시"  P5 Project                            ← 다른 계약이다
```

`references.jsonl`(정정 체인 전용 아티팩트)만 쓰도록 고쳤다. 그런데 그것도
*(날짜, 서식명)* 으로 풀어서 **같은 날 같은 서식이면 후보가 여럿**이다. 그래서
**계약명이 같은 후보만** 원공시로 인정한다. 후보가 **하나뿐이어도 계약명이 다르면
쓰지 않는다** — 그 분기를 켜 봤더니 가짜 짝이 넷 더 나왔다:

```
VLAC 2척            ↔ 157,000 DWT 원유운반선 2척
신고리5,6호기         ↔ 새울3,4호기
블록 및 기자재        ↔ 블록, 기자재 및 설계   (같은 날 둘이 서로를 가리킴)
투자판단 관련 주요경영사항 ↔ 광명시흥 공공주택건설사업
```

🔴 **참을 하나 놓치는 것이 거짓을 하나 싣는 것보다 낫다.** 체인(`targets`)은 그대로
보여 주므로 사람이 후보를 볼 수 있다.

**결과 (정정 631건)**

```
원공시 확정      305      금액 비교 가능 290 · 🔴 금액이 실제로 바뀐 것 144 · 그대로 139
후보만 있음       17      ambiguous_targets — 체인은 보여 주고 금액은 비운다
추적 실패        309      before_corpus 203 · no_reference 103 · not_found 3
```

`resolved=false` 를 전부 담고 사유를 붙였다 — 감추면 목록이 실제보다 완전해 보인다.
