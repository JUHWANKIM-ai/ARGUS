# ① 메타 축 LOO — `L6`·`L7`·`L8` (커밋 `19d4544`)

## 무엇을 했나 — v3 의 *"구조적으로 측정 불가"* 는 틀렸다

표현 자리는 **`search_chunks` 의 인자**였다. LOO = *"그 인자를 넘기지 않는다"* 이고,
검색 단계를 끄는 것이 아니므로 **BM25 는 그대로 돌고 후보 집합만 넓어진다.**

```

L7  meta_date    ym · year · rcept_dt     → prefix["rcept_dt"] (셋 다 같은 축으로 접힌다)
L8  meta_group   group                    → _group_index(target) · 빠지면 exchange 로 떨어진다
```

🔴 **`base_year`(사업연도)·`doc_subtype` 은 안 뗐다.** 접수연도 ≠ 사업연도이고
(`query.plan_section_hops` 주석 1번 — '2023년 사업보고서' 는 2024-03 접수), 함께 떼면
`L7` 이 접수일 축 하나의 Δ 를 못 낸다.

셋을 `LOO_REMOVED` 에 넣었다 — 곁가지가 아니라 **LOO 표의 빈칸**이다. `L5` 는 v3 가 기각한
이름이라 **건너뛰고** `L6`·`L7`·`L8` 을 썼다.

## 🔴 `META_UNREACHABLE_FLAGS` — 넣을 수 없었다. 대신 축을 신설했다

그 목록은 `True = 그 구성요소를 켠다` 를 전제로 **'켜져 있으면 예외'** 를 던지는데,
메타 축 플래그는 **기본값이 `True`(= 축을 넘긴다)** 라서 넣는 순간 `A0` 자신이 예외가 된다.
그래서 `META_UNREACHABLE_AXES` 를 신설하고 `ORACLE_UNREACHABLE_FLAGS` 와 같은
**'기본값에서 움직였는가'** 형태로 막았다. 근거는 코드다 — `_gather_meta` 는
`search_chunks` 를 한 번도 부르지 않고 `filter_docs` 만 쓴다. 셋을
`ORACLE_UNREACHABLE_FLAGS` 에도 넣었다(골든 주입은 검색 차선을 안 탄다).

# ③ `A10` — 자기일관성 `k=3` · 온도 0.7

## 🔴 온도 이관 — **회귀 확인이 이 태스크의 핵심이었다**

온도 0.0 은 `pipeline.answer_question` 에 직접 하드코딩돼 있었고 `Arm` 에 표현할 자리가
없었다(`R0-5`). `Arm.temperature: float = 0.0` · `Arm.sc_k: int = 1` 을 신설하고
답변 생성 호출만 `arm.temperature` 를 읽게 했다.

**안 옮긴 곳 셋 — 의도적이다**

```
_regenerate_once (A20r)   온도 0.0 유지. 저쪽이 재는 것은 **진단 주입**이고 온도를 함께
                          올리면 그 Δ 에 다양성의 몫이 섞여 두 arm 을 못 비교한다
critic.judge              채점 인프라다. 비결정적 채점은 세대 간 비교를 통째로 깬다
critic.judge_open         같다
```

**🔴 `A8` 이 바이트 동일인가 — 전수 대조 (0원 · LLM 0회)**

```
$ ablation.py --arm A8 --cohort full --out artifacts/ablation/v4 --offline
  → 캐시 미적중 0 · 신규 지출 0.0원
  → A8 report.json 88행 **전 필드 동일** (answer · think_trace · 토큰 · 정오 · totals)
```

🔴 **`--offline` 이 통과한 것 자체가 증명이다.** 요청 캐시 키는 `sha256(url + body)` 이고
`body` 에 `temperature` 가 들어 있다. 온도가 한 arm 이라도 흔들렸으면 그 arm 의 캐시가
전량 미적중이 되고 `--offline` 이 첫 문항에서 죽는다. 미적중 0 = **요청 본문이 바이트
동일**이다. 그리고 `A8` 아닌 arm 도 `test_temperature_moved_to_the_arm_but_the_default_is_still_zero`
가 `ARMS` 전량에 대해 `temperature == 0.0 and sc_k == 1` 을 단언한다(`A10` 만 예외).

## 🔴 구현하면서 닫은 함정 둘 — 둘 다 Δ 를 조용히 0 으로 만든다

### ① 요청 캐시가 k 개 표본을 하나로 접는다

`RequestCache._key` 는 `url + body` 해시다. SC 의 표본은 **프롬프트도 온도도 같으므로
캐시 키가 하나**다. 그대로 두면 2·3회차가 1회차 응답을 적중시켜 표본이 전부 같아지고,
다수결이 **공짜 만장일치**가 된다. 같은 사고를 judge 재현 편차에서 이미 겪어
`RequestCache.no_cache()` 가 그 자리에 있다.

파이프라인은 러너를 import 할 수 없으므로 신호를 `argus.clova` 모듈 전역에 두고

## 🔴 가장 큰 발견 — **다수결이 성립하지 않는다**

트레이스의 `sc k=3/3 temp=0.7 keys=N votes=M picked=P` 를 12문항 전량에서 읽으면:

```

```

즉 **자기일관성 논문의 전제 — *"여러 갈래로 추론해도 같은 답으로 수렴한다"* — 가 이
코호트에서 성립하지 않는다.** 다수가 없으니 동수 규칙(먼저 나온 키)이 항상 이기고,
`A10` 이 실제로 재고 있는 것은 *"온도를 0.7 로 올린 `A8`"* 이다.

🔴 **이 값은 `_sc_key` 의 정의에 의존한다.** 표본을 묶는 키를 답변의 **금액·비율 전량**
(`critic._money_spans` + `critic._PCT_RE`)으로 잡았다. 닫힌 문항의 채점 축이
`em:number_won` 이라 그 선택에 근거가 있지만, 더 거친 키(예: 첫 금액 하나)를 쓰면
다수가 생길 수 있다. **그 대안은 재지 않았다** — 표본 2·3회차의 원문을 저장하지 않아
0원으로 재분석할 수 없다(다음 라운드가 재려면 표본 키를 트레이스에 남겨야 한다).
