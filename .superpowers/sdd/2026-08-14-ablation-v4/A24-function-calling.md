## §1. 구현 — 🔴 **왕복은 구현돼 있지 않았다. 만들었다**

### 있던 것 / 없던 것

| | 상태 |
|---|---|
| `tools.TOOL_SPECS` 15종 (검색 8 + 계산 7) | 🟢 v1 부터 있었다 |
| `tools.execute()` 디스패치 | 🟢 있었다 (회귀 테스트도 있었다) |
| `clova.chat(tools=…)` 인자 | 🟢 **있었다** — `body["tools"]` + `toolChoice="auto"` |
| `ChatResult.tool_calls` (`toolCalls` 파싱) | 🟢 있었다 |
| 🔴 **`tools=` 를 넘기는 호출부** | ❌ **저장소 전체에 0건** |
| 🔴 **`tool_calls` 를 소비하는 코드** | ❌ **0건** — 필드를 파싱만 하고 아무도 안 읽었다 |

**즉 왕복은 절반만 있었다.** 나가는 길(`tools=`)과 돌아온 것을 담는 그릇
(`ChatResult.tool_calls`)은 있는데, **그릇을 열어 실행하고 다시 넣는 부분이 없었다.**

### 만든 것

```
src/argus/ablation.py       Arm.function_calling: bool = False      (플래그)
                            A24 = replace(A8, name="A24", function_calling=True)
                            RUN_ORDER 에 A18 뒤 · dense 앞으로 삽입
src/argus/agent/pipeline.py _answer_with_tools()  ← 🔴 왕복 본체
                            _tool_arguments()     ← arguments 사전/JSON문자열 양쪽 수용
                            answer_question() 에서 arm.function_calling 으로 분기
tests/test_function_calling.py  19건
```

**왕복의 형태** (`_answer_with_tools`):

```
① chat(convo, tools=TOOL_SPECS)              ← 🔴 maxTokens 를 못 준다 (40001)
   toolCalls 가 없으면 그 본문이 답이다. 끝
② convo += {"role":"assistant", "content":…, "toolCalls":[…]}
   각 call 마다 tools.execute(name, args) → {"role":"tool","toolCallId":…,"content":…}
③ chat(convo)  ← 도구를 빼서 maxTokens=300/800 을 되돌린다. 그 본문이 답이다
```

- **`MAX_TOOL_ROUNDS = 1`** — 생성 호출은 문항당 **정확히 1~2회**. 루프를 열면 문항당
  비용 상한이 사라진다(`pipeline.py` 머리말: 고정 횟수 단계).
- **`MAX_TOOL_RESULT_CHARS = 2,000`** — `read_section` 은 수만 자를 돌려준다. 상한이
  없으면 토큰 상한 20,000 을 한 번에 태우고 `UNANSWERABLE` 이 나가 **그것이 측정으로
  굳는다.**
- **첫 호출이 죽으면 그대로 올려보낸다** — 상류 장애가 arm 효과로 섞이지 않게.
  2회차부터는 이미 받아 둔 본문을 지키고 멈춘다(`_self_consistent` 와 같은 규약).


**도출 과정과 접수번호 인용을 통째로 잃고** `(근거: 비교 공시, 2024-11-15)` 로 줄었다.
수치 자체(`7,581,628,000`)는 맞는데 **근거를 못 대서** 채점에서 졌다.

**② `tools` 와 `maxTokens` 가 배타라 길이 상한이 사라진다.**
`Q-106` 은 **도구를 한 번도 안 불렀는데** 회귀했다 — 순수 디코딩 조건 변화만으로 답이
흔들린 증거다. 이것은 우리 설계가 아니라 **API 제약**(40001)이고, `tools=` 를 켜는 한
피할 수 없다.

## §6. 게이트 F 확정 — ❌ **기각**

§0 에 미리 못 박은 규칙:

```
Δ ≥ 0 이고 회귀 0      → [x] 채택
Δ < 0 또는 회귀 있음   → ❌ 기각
```

**Δ = −6(그리드) · −7(전체 88) · 0(밸류체인) · 회귀 9건 → 두 조건 다 기각 쪽이다.**

`docs/pipeline/06-agent-tool.md` 게이트 F 를 이렇게 바꿨다:

```
종전  - [~] 계산 함수 7종이 TOOL_SPECS 에 등록됨 — 🔴 function calling 으로 호출되지는 않는다
현재  - [x] 계산 함수 7종이 TOOL_SPECS 에 등록됨 · 🔴 function calling 은 연결해서 재고 ❌ 기각했다
```

🔴 **`[x]` 로 올린 것은 "등록" 항목이 닫혔기 때문이고, function calling 자체는 `❌` 다.**
두 사실을 한 줄에 함께 적었다 — `[x]` 만 보고 *"function calling 이 돌고 있다"* 로 읽히면
`A5` 의 Δ 해석이 다시 뒤틀린다(`09 §I-5f ②`: `A5` 의 Δ 는 근거에 박아 둔 계산 결과에서
온다).

**기본값은 켜지 않는다.** 운영 기본값 `ablation._current = A20r` 은 그대로이고
`function_calling=False` 다. **평가 서버 재배포 불필요.**

**같이 고친 문서 넷** (한쪽만 고치지 않는다):

```
src/argus/ablation.py            머리말 §calc_values 절 + A24 블록에 기각 사유 전문
docs/pipeline/06-agent-tool.md   F-1 표 · 게이트 F
docs/pipeline/09-ablation.md     §I-5f ⑧ `A24` 행(🔶 미판정 → ❌ 기각) · §I-2 표 · §I-5f ②
paper/base/base.md               §7 판정표 · 계보 그림 · 「Toolformer 최종 판정」 절 신설
```

   죽였으므로 그 변형의 상한은 0** 이다 — 그래서 세우지 않았다.
   🔴 **이것은 측정이 아니라 추론이다.**
4. **도구 연쇄(`calc_total` → `calc_share`)는 구조적으로 못 한다** (`MAX_TOOL_ROUNDS=1`).
   상한을 2 로 올리면 문항당 생성 3회가 되어 토큰 상한 20,000 을 태울 위험이 있다.
   현 실측에서 2회차에 **또** 도구를 부르려 한 문항이 몇 건인지는 **세지 않았다.**
5. **`Q-034`(전체 88 에서 유일한 개선)의 성질을 파고들지 않았다.** `A24` 가 해지 3건 중
   `㈜태영건설` 항목을 **빠뜨렸는데** 채점은 정답으로 셌다 — 🔴 **채점 결함일 수 있다.**

   🔴 **즉 "새로 맞춘 것 2건" 은 둘 다 채점기 쪽 의심이 있다.**
7. **`--force` 를 쓰지 않았다.** `A24` 는 새 arm 이라 캐시가 없고, `--offline` 이
   **전량 미적중으로 즉시 정지**한 것이 그 증명이다(캐시 적중 0). no-op 위험 없음.
