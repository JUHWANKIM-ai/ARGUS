**범위**: `A24`(function calling · ❌ 기각 · 그리드 −6)의 **기각 사유 셋을 하나씩 겨냥한
재시도**를 세우고 잰다. `A24` arm 은 지우지 않는다 — 기각 판정의 물증이다.

```

② 근거 희석           calc_tools_only          계산 7종만 내민다 (검색 8종을 뺀다)
```

**`A24` 는 도구를 안 불러서 진 것이 아니다** — 88문항 중 37문항(42.0%)이 실제로 불렀다.

**우리 도메인의 병목은 산술이 아니라 전사다.** `A20`(재계산값 치환)이 이기는 이유가

### 🔴 왜 `Arm` 하위 옵션인가 — 코드를 읽고 정했다

사용자 지시는 *"새 arm 이름 둘 또는 `function_calling` 의 하위 옵션 중 더 깔끔한 쪽"*
이었다. **하위 옵션을 골랐고 근거가 셋이다.**

**① `Arm` 은 이미 부모/자식 구조를 데이터로 갖고 있다.** `FLAG_DEPENDENCIES` 에
`verifier -> (substitute_verified, provenance_gate, regenerate_on_verify)` 가 그대로
있고, 셋 다 *"부모가 꺼지면 코드가 도달하지 않는다"* 는 **같은 종류의 구조적 의존**이다.
새 셋도 `_answer_with_tools`/`_offer_tools` **안에서만** 읽히므로 정확히 같은 자리다.
산문으로 적으면 `__post_init__` 이 그것을 못 읽는다 — 데이터로 두면 검사가 따라온다.

**② 뭉치면 사후에 분해할 수 없다.** `A24b` 는 조작이 셋인 arm 이다. 플래그로 갈라 두면
나중에 `A24b − calc_tools_only` 같은 부분 arm 을 **한 줄로** 세울 수 있고, 셋 중 어느
것이 Δ 를 냈는지 물을 수 있다. 이름 하나로 뭉치면 그 질문 자체가 코드로 표현되지 않는다.

**③ 기존 검사가 그대로 붙는다.** `test_loo_arms_differ_from_a8_by_exactly_one_flag` 가
`FLAG_DEPENDENCIES` 를 읽어 예외를 허용하고, `FLAG_NAMES` 는 `__dataclass_fields__` 에서
자동으로 잡으므로 새 스위치가 **LOO 의 단일 변수 조작 검사에 자동으로 들어온다.**

🔴 **`A24` arm 정의는 한 글자도 안 바꿨다** — 기각 판정의 물증이고, 그 arm 의 산출물
(`artifacts/ablation/v4/A24`)도 건드리지 않았다. `test_a24_is_not_deleted_and_still_differs_from_a8_by_one_flag`
가 그것을 못 박는다.

## §3. ③의 선택 — 🔴 **(a) 를 골랐다**

**(b) 를 먼저 봤다.** `clova.chat` 이 요청 본문에 싣는 축은 `messages` ·`temperature` ·
`topP` · `repeatPenalty` · `maxTokens` · `tools` · `toolChoice` 뿐이고, 이 중 길이를
제한하는 것은 **`maxTokens` 하나**다. 그리고 그것이 `tools` 와 배타다(40001 ·
`clova.py` 머리말). 🔴 **주최측 문서에는 왕복 형식조차 없어서**(`A24` §1 — 우리가
라이브 스모크로 형식을 확인했다) *"다른 길이 축이 API 에 있는가"* 는 **문서로 확인할 수
없었다.** 그래서 (b) 를 쓸 근거가 없다.

**프롬프트로 길이를 지시하는 안도 버렸다** — 그것은 API 축이 아니라 **규칙을 하나 더

| 프롬프트 토큰 | +8% ~ +18% | **+29.1%** | 🔴 **구간 밖** — 스펙 크기만 셌고 **왕복 2회차의 프롬프트 재적재**를 뺐다 |
| `llm_calls` | 140 ~ 155 | **157** | 🔴 살짝 밖 |
| 지출 | 1,200 ~ 2,000원 | **약 1,804원** | 🟢 구간 안 |
| 🔴 **`A24b+A20` 그리드** | 66 ~ 68 · 가장 그럴듯 **67** | **64** | 🔴 **구간 밖 · 3 낮다** |
| `A24b+A20` 지출 | 0원 근처 | **0.0원** (적중 195/0) | 🟢 적중 |
| 도구 호출 (예측 ⑤) | 계산 호출이 **늘 수 있다** | 21 → **29건 (+38%)** | 🟢 적중 |

🔴 **가장 값진 오차는 결합 예측이다.** 나는 *"두 치환은 원천이 달라 겹치지 않는다"* 를
가정했는데 실측은 **앞의 조작이 뒤의 조작의 전제를 부순다**였다(§4c). 그 기전은
**`A20` 을 `A8` 이 아닌 다른 생성 위에 올린 첫 측정**이 드러낸 것이다.

**두 번째 오차 — 토큰.** 왕복이 프롬프트를 통째로 다시 싣는다는 것은 코드에 그대로
적혀 있었는데(`convo` 를 이어 붙인다) 예측에서 도구 스펙 크기만 셌다.

## §6. 판정 — ❌ **기각**

§0 에 미리 못 박은 규칙:

```
[x] 채택 후보    Δ(A8 → A24b+A20) > +2 (그리드 68 이상) 이고 A20 대비 회귀 0
❌ 기각          그 외 전부
```

**실측 Δ(A8 → A24b+A20) = −1 · `A20` 대비 회귀 5건 → 두 조건 다 기각 쪽이다.**

```
A8  65/72     A20  67/72 (0원)     A24  59/72     A24b  64/72     A24b+A20  64/72
```

🔴 **그러나 이 라운드의 산출물은 판정이 아니라 기전 셋이다.**

**① `A24` 의 기각 사유 셋 중 둘은 실제로 고쳐졌다.** 그리드 `59 → 64`(+5) · 회귀
`9 → 5` · 프롬프트 토큰 `+44.0% → +29.1%` · 검색 도구 호출 `26건 → 0건`. 즉
*"function calling 은 우리 도메인에서 통째로 안 된다"* 가 아니라 **어느 부분이 얼마나
나쁜지**를 분해할 수 있게 됐다. `A24` §9 ③ 이 *"`_CALC_SPECS` 만 내미는 변형의 상한은
0"* 이라고 **추론**했는데 실측은 **+5** 였다 — 🔴 **그 추론은 틀렸다.**

**② 🔴 그런데도 `A8` 을 못 넘는다.** 남은 −1 의 정체가 §4a·§4b 다: 전사 오류가 사라진
것이 아니라 **답변에서 도구 인자로 옮겨 갔고**(`Q-047`·`Q-051`), 길이 상한 소실이 계산
질의 안에서는 그대로 남는다(`Q-106`).

**③ 🔴 도구는 `A20` 을 무력화한다** (§4c). 제안서에서 이 대비가 `A24` 단독보다 강하다 —
*"같은 표적을 두 방식으로 풀었고, 둘을 합치면 서로를 깎는다."*

**기본값은 바꾸지 않는다.** `ablation._current = A20r` 그대로이고 `function_calling` ·
`calc_tools_only` · `calc_queries_only` · `substitute_tool_results` 는 운영 경로에서
전부 `False` 다. **평가 서버 재배포 불필요.**

1. **`heldout` 은 열지 않았다.** 판정은 **보이는 100문항**(전체 88 + 밸류체인 12)에서만
   유효하다.
2. **안전성 코호트(12문항)로는 안 쟀다.** `A24b` 가 거절 경로를 건드리지 않는 것은 전체
   88 에서 확인했다 — 생성에 도달하지 않는 6문항은 `fc gate=` 가 아예 안 찍힌다.
3. 🔴 **`400 40009 Unsupported function` 의 원인을 특정하지 못했다.** 도구 왕복 약 40회 중
   2회이고 재시도로 둘 다 통과했다. **처방을 넣지 않았다** — 지금 `with_retry` 나
   `_answer_with_tools` 를 고치면 이번 측정의 조건이 바뀐다. 🔴 **다음 라운드가 도구를
   쓴다면 반드시 먼저 처리해야 한다** (런이 통째로 죽고 원장에 구멍이 난다 — §4).
4. 🔴 **원장 밖 지출 약 864원**(크래시 784 + 프로브 80). `run.json` 재귀 합 9,561.0원은
   그만큼 **작게** 찍혀 있다.

   arm 은 플래그로 한 줄이면 세울 수 있게 해 뒀지만(§1 ②), 판정이 이미 기각이라 돈을 더
