## ① `Q-108` 정규식 — **기각.** 진단과 기전이 다르다

`R1-6` 보고서는 *"`_COUNTERPARTY_ROLE` 정규식이 '…와' 조사를 못 잡아 hop 미발화"* 로
짚었다. 먼저 정규식의 자리부터 다르다 — 계획서 Files 는 `pipeline.py` 라고 적었지만
실제 위치는 **`src/argus/agent/router.py:257`** 이다.

`Q-108` 원문(저장 응답에서 읽음 · `evalset/` 미접촉):

> 체코 두코바니 5·6호기 원자력발전소 사업에서 **두산에너빌리티와 한전기술이** 공시한
> 계약들은 발주-수주 관계로 어떻게 이어지는가?

`canonical()` 뒤 노드 `두산에너빌리티` 의 **잔여 문자열**은 `와한전기술이공시한…` 이다.
이 정규식은 `조사 + 표지`(`계약상대`·`발주`) **인접**을 요구하는데, `와` 뒤에 오는 것이
표지가 아니라 **다른 회사 이름**이다. 즉 `와|과|및` 을 더해도 **매치할 자리가 없다.**

**실측 (LLM 0회 · 검색 0회 · 전체 88 + 밸류체인 12 = 100문항 전량):**

```
현재 정규식        발화 9건
와|과|및 추가      발화 9건        새로 잡히는 문항 0건 · 잃는 문항 0건
```

그리고 매치했더라도 **틀린다.** 이 문장에서 두산에너빌리티·한전기술은 둘 다
**공시한 쪽**이다. 결속하면 `query_by_counterparty` 가 역방향 근거를 싣는다 —
`router.py:216-225` 가 이미 실측 오탐 3건으로 `와|과` 를 기각해 뒀고
`test_conjunctive_particles_do_not_bind_the_role` 이 그 경계를 들고 있다. 같은 파일
`:188-190` 은 `Q-108` 을 이름으로 짚어 *"발주처인 것은 본문이 아니라 답에서 드러나는
사실이라 규칙으로는 안 잡히고, 그 hop 이 `Q-108` 에 기여한 골든도 0건"* 이라고 적어 뒀다.

→ 소스 주석에 기각 근거를 남기고 `test_the_q108_conjunction_is_not_a_role_binding` 로
고정했다. **정규식은 한 글자도 안 바꿨다.**

## ③ `_enumerate_events` `depth < 1` — **기각.** 하중 상수가 이것이 아니다

계획서 지시대로 `MAX_EVIDENCE`(10)·`MAX_SECTION_CHARS` 와 부딪히는지 **먼저** 확인했고,
확인하는 과정에서 더 앞의 상수가 걸린다는 것이 나왔다.

**실측 `Q-117` (한전기술 · `단일판매공급계약체결` · pool=27):**

```
계약상대 그룹 = 11개                MAX_ENUM_EVIDENCE = MAX_EVIDENCE // 2 = 5
depth<1 -> 5건    depth<2 -> 5건    depth<3 -> 5건        (집합이 전부 동일)
```

그룹이 11개인데 담을 칸이 5개뿐이라 **`depth 0` 한 바퀴에서 이미 상한이 찬다.**
둘째 바퀴가 아예 안 돈다 — `depth` 를 올리는 것은 이 코퍼스에서 **엄밀한 no-op** 이다.

열거 hop 이 발화하는 문항은 100문항 중 **`Q-117` 하나뿐**이다(전수 확인). 그러므로
"다른 문항에서는 depth 가 하중일 수 있다" 는 여지도 없다.

**미회수 3건의 실제 위치:**

| rcept_no | 그룹 | 실제 원인 | 필요한 것 |
|---|---|---|---|
| `20260209801845` | 한국남부발전 **1건짜리** | depth 0 인데 그룹 순위 9/11 | `MAX_ENUM_EVIDENCE >= 9` |
| `20251224800396` | 두산에너빌리티 2번째 | 전체 13번째 | `>= 13` |
| `20230330800844` | 두산에너빌리티 4번째 | 전체 20번째 | `>= 20` |

첫 건은 **1건짜리 그룹**이라 depth 와 아무 관계가 없다 — 순위가 상한 밖일 뿐이다.
그리고 최종 절단이 `picked[:MAX_EVIDENCE]`(10)이고 `MAX_ENUM_EVIDENCE` 는 그 **절반**이라
(열거가 검색 근거를 밀어내지 않게 하려고 그렇게 뒀다) 셋을 다 회수하려면 `MAX_EVIDENCE`
자체를 올려야 한다 — **그것이 `A16` 이고 `R0-3`(`dac2bf0`)이 이미 기각했다.**

🔴 `R0-3` 이 실측한 *"`MAX_EVIDENCE` 초과 문항은 `Q-023` 하나뿐"* 은 **검색 근거 쪽의
여유**이고, `Q-117` 이 부딪히는 것은 그 앞단의 **열거 몫(5칸)** 이다. 두 상수를 같은
것으로 읽으면 여유가 있다고 오판하게 된다.

→ 소스 독스트링에 실측을 남기고
`test_the_evidence_cap_binds_before_the_group_depth` ·
