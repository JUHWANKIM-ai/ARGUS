### ① `Q-018` — 🔴 **기전은 겨냥대로 열렸고, 답은 더 나빠졌다**

```
A8       답 1,843,200,000,000  (근거 1,842,200,000,000 — 13자리 중 한 자리)
         calc_checked  [equation, restatement]      gated 2   critic_supported True
         critic_passed_wrong_answer  True           amount 검사는 게이트로 꺼짐

A8-lean  답 "계약금액은 3,759억원 증가"
         최초 15,663,000,000,000원 / 최종 18,422,000,000,000원   ← 🔴 둘 다 10배
         calc_checked  [amount, equation]           gated 0   critic 미호출(인용 있음)
         critic_passed_wrong_answer  False          🔴 amount 3건 + equation 1건 발화
         failure_why  equation 18,422,000,000,000 − 15,663,000,000,000 = 3,759,000,000,000
                      vs 재계산 2,759,000,000,000
                      amount 15,663,000,000,000원 vs 1,566,300,000,000 (10^+1 자릿수)  ×3
```

읽는 법 셋:

1. 🔴 **R2+ 의 기전 진단이 실측으로 확인됐다.** *"규칙이 답변 어휘를 바꿔 검증 게이트를
   닫았다"* — 규칙을 빼자 답변이 `계약금액` 을 되받아 쓰고 **게이트가 열렸다**
   (`calc_gated_records` 2 → 0). 전체 88 합계로도 **22 → 16**(−6 · `Q-018` 2→0 ·
   `Q-061` 3→0 · `Q-087` 1→0), `critic_passed_wrong_answer` **4 → 3**.
   **탐지력은 실제로 올라갔다.**
2. ❌ **정답률은 안 올랐고 답변 품질은 내려갔다.** 규칙 9(*"차이·합계는 원 단위 원값으로,
   괄호 표기를 그대로"*)가 없어지자 모델이 **억 단위로 계산해 원으로 되돌렸고**
   (`18,422억 → 15,663,000,000,000원`) 거기서 10배가 났다. 뺄셈까지 틀렸다
   (`18,422 − 15,663 = 3,759`, 실제 2,759). **한 자리 전사 오류가 세 자리 스케일
   오류로 바뀌었다.**
3. 즉 이 문항에서 규칙 8·9 는 **검증을 가리는 대가로 답을 지키고 있었다.** 그 거래를
   되돌리면 검증은 보이는데 답이 더 틀린다. **어느 쪽도 정답이 아니다** — 처방은
   규칙 제거가 아니라 `_says_amount` 게이트 쪽(보류 `I-2`)이다.

### ② `Q-023` — 오답 유지. 실패 내용은 그대로다

`narrative` · `GENERATION/REASONING` 불변. 두 답변 다 *"계약금액에는 변동이 없었다"*
(골든은 정정 5회의 금액 변동). A8-lean 답변은 정정 4건을 **더 자세히 열거**했지만
금액 변동을 여전히 못 읽었다. `critic_supported` True 도 그대로다.
🔴 **이 문항의 겨냥은 ② 축(근거 희석 제거)이고 이 arm 은 ① 축만 조작한다** — 프롬프트가
224자 짧아진 것으로는 안 움직였다. `A12`(critic 상시화)의 유일한 겨냥이 이 문항이므로
**`A12` 를 되살리는 조건이 충족됐다**(R2+ §4-`A12`: *"`A8-lean` 이 `Q-023` 을 못 고치면"*).

### ③ `Q-044` — 🔴 **이 arm 의 사정거리 밖. 정의상 불변이다**

`Q-044` 근거(정기공시 10,290자)에는 조 단위 `억원` 괄호가 **없다** →
`split_trillion_eok` 발화 0 → 규칙 8·9 가 **애초에 안 붙는다** → 프롬프트가 **바이트
동일** → 요청 캐시 적중 → **답변이 바이트 동일**(`1,699,923 + 665,945 = 1,365,868`).

🔴 **그러므로 이 문항을 "A8-lean 이 못 고쳤다" 로 세면 안 된다** — 잰 적이 없다.
R2+ 가 이 문항을 A8-lean 의 겨냥에 넣은 것은 **② 축(근거 재순위)** 이기 때문이고,
이 라운드는 ② 축을 **구현하지 않았다**(§7).

## 9. 🔴 확신하지 못하는 것

1. **`Q-018` 의 어휘 전환에서 규칙 5 의 몫을 못 갈랐다.** 규칙 8·9 를 빼자 게이트가
   열린 것은 **8·9 가 관여했다**는 증거지만, `최초 공시 금액` 이라는 표현 자체는 규칙 5
   어휘와 겹친다. 규칙 5 는 뺄 수 없으므로(정정 채점 직결) **이 갈림은 이 arm 으로는
   닫히지 않는다.** 닫으려면 규칙 5 만 문안을 바꾼 별 arm 이 필요하고, 그것은
   채점 축을 건드리므로 값이 낮다고 판단했다.
2. **표본이 작다.** 규칙 8·9 노출은 전체 88 중 **16문항**이고 그중 오답이 4건이다.
   *"정답률 Δ = 0"* 은 **16문항 안에서의 0**이다. 3의 법칙으로, 16문항에서 개선 0건이면
   참 개선율의 95% 상한은 **약 17%**(≈2.7문항)다. **"효과가 정확히 0" 이라고 주장하지
   않는다 — 이 16문항에서 0 이었다고 주장한다.**
3. **밸류체인 12 의 `+8.3%p`(부풀림 기준)를 내가 개선이 아니라고 판정한 것은 기전
   해석이다.** `checked=[]` 와 금액 미기재는 산출물로 확인했지만, *"그 답변이 A8 답변보다
   실질적으로 나쁘다"* 는 **judge 가 동의하지 않았다**(둘 다 정답 처리). 내 판정은
   *"공시 QA 로서 금액을 안 쓰는 답이 더 낫다고 할 수 없다"* 는 도메인 판단이고,
   채점기로는 뒷받침되지 않는다.
4. **② 축(근거 재순위)을 안 쟀으므로 `A8-lean` 이라는 이름의 절반은 미측정이다.**
   R2+ 가 이 arm 에 부여한 겨냥 3건 중 **2건이 ② 축**이다. 이 기각을 *"A8-lean 전체의
   기각"* 으로 인용하면 안 된다 — **① 축의 기각**이다. 이름이 같아서 생길 오독이
   가장 걱정된다.
5. **`Q-087` 은 이 arm 의 겨냥이 아니었는데 게이트가 1 → 0 으로 열렸다.** R2+ §3 이

   (`VERIFY/VERIFY` 는 유지됐다). 확인하지 않았다.
6. **비용 예측이 왜 빗나갔는지는 확실하지만, 그 방향이 다음에도 유지될지는 모른다.**
