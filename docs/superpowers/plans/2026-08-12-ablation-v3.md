## 코드가 이미 판정해 둔 것 — 실측 3근거

겨냥은 실재하고 성질도 맞다 — 5건 전부 *"어려워서 틀린 것"* 이 아니라 **전사·덧셈 실수**다
(`Q-018` 13자리 중 한 자리 · `Q-044` `1,699,923+665,945` 를 `1,365,868` · `Q-097` 나눗셈 ·

`number_won` 28 + `boolean` 5 = **33/88** 로 종전 계산과 같고, `narrative`·`list` 3건
(`Q-023`·`Q-087`·`Q-093`)과 밸류체인 2건(`Q-117`·`Q-110`)은 **논문이 명시한 한계**로 뺀다.
🔴 **난이도로 좁히면 안 된다는 정정도 유효하다** — 겨냥 5건이 상 1(`Q-018`) · 중 4다.

그런데도 보류하는 이유 셋:

1. 🔴 **0원 대안이 같은 5건을 정확히 겨냥한다.** 5건 전부 **우리 결정적 검사가 이미
   잡고 있다** — `verify_answer_arithmetic`(`restatement`·`equation`)과
   `verify_calculation`(`per_unit`·`amount`)이 발화해 답변 끝에
   `(주의: 자동 검증에서 결함이 발견되었습니다 — …)` 꼬리까지 붙어 있다. 즉 **탐지는
   이미 되고 파이프라인이 그것으로 아무것도 하지 않는다.** 검사가 발화하면 **재생성
   1회**를 돌리는 것은 크레딧 0원 코드 수정이고, `A4-rr` 판정이 세운 규칙
   (*"겨냥이 겹치면 크레딧 0원이고 위험 없는 쪽을 먼저 세운다"*)이 그대로 적용된다.
2. 🔴 **온도 통제 변수 + 캐시 우회.** SC 는 온도>0 을 요구하는데 **온도 0.0 은
   `09-ablation §I-3` 의 통제 변수**다. 세우면 `k=1·온도>0` 대조군이 **필수**다 —
   없으면 Δ 를 `SC 효과 + 온도 효과` 로 읽는다. 그리고 요청 캐시 키가
   `sha256({url, body})` 이고 `body` 에 `temperature` 가 들어 있으므로 **k=3 의 세
   호출이 바이트 동일한 body 를 보낸다** → 안 우회하면 **세 번이 같은 응답을 받아
   다수결이 무의미해진다.** `RequestCache.no_cache()` 로 우회해야 하고, 우회 호출은
   **캐시에 쓰지 않으므로 재실행마다 전액을 다시 낸다.**
3. **비용 예측이 종전의 배다.** 종전 견적은 *"66회 추가 ≈ 1,500원"* 이었는데, 우회와
   대조군을 세면 아래 표대로 **전체 88 에서 2,794.0원**이다.
4. 🔴 **저장소에 이미 있는 `sc` 플래그는 쓸 수 없다 — 그것이 바로 그 범위 오류다.**
   `router.py:78` 의 `Route.use_sc` 가 세 자리에서 켜지고(`complex_reason`/`multi_compare`
   × `difficulty=high`) `pipeline.py:1833` 이 `think_trace` 에 `sc=True` 를 **찍는다** —
   현 세대 실측 **전체 88 중 19문항 · 밸류체인 12 중 8문항**. 🔴 **그런데 그 값을 소비하는
   코드가 없다**(유일한 독자가 그 trace 한 줄이고 답변 생성은 언제나 1회다) — **죽은
   플래그**이고 산출물은 일어나지 않은 일을 적고 있다. 그리고 그것을 되살려 트리거로 쓰면
   **그리드 72 겨냥 3건 중 2건을 놓친다**:

   ```
   Q-018  sc=False  route=closed_lookup  난이도 상   <- 놓친다
   Q-044  sc=True   route=multi_compare  난이도 중
   Q-097  sc=False  route=closed_lookup  난이도 중   <- 놓친다
   ```

# Phase 1b — 🔴 그래프 2-hop 재검토를 **닫는다** (T5)

## 🔴 먼저 범위를 못박는다 — 그래프는 **기각된 것이 아니다**

**"GraphRAG 기각" 은 엣지 하나에 대한 판정이다.** 기각한 것은 `기업 —계약했다→ 기업`
직접 엣지(29쌍 · 완결도 1.2%)와 커뮤니티 탐지뿐이고, **노드·엣지를 코퍼스에 맞게
재정의한 쪽은 우리 성적의 대부분을 만든다** — 아래 셋 다 두 판에서 재현된 실측이다.

| 재정의한 것 | 실측 기여 | 기전 |
|---|---|---|
| `공시 —정정한다→ 공시` 550엣지 **순회** | **L1 = −9.7%p** (62→55/72) | 근거도 112→**98** 동반 하락 = **검색이 못 찾는다** |
| **n-ary 이벤트 노드** 속성 (major·holding) | **L2 = −15.3%p** (62→51/72) | **최대 병목.** 근거 112 그대로인데 정답 11건 적다 = 생성이 못 쓴다 |
| 2부 그래프를 **탐색 아니라 메타 축으로** | **A1→A1b = +41.7%p** | 사다리 최대 전이. `doc_subtype` 문서군별 색인 |
| `기업 —(계약상대)— 기업` **2-hop** | 🟡 그리드 **+0.0%p** | **T5 가 겨냥하는 것은 이것 하나다** |

**T5 는 그래프의 채택 여부를 다시 묻는 태스크가 아니다.** 그것은 이미 위 세 줄로 답이 났다.
T5 가 묻는 것은 **네 번째 줄, 유일하게 미확정인 엣지 하나**다.

## 그 하나가 세 라운드 동안 안 닫혔다
