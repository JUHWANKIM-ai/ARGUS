### ★ `ORACLE` — 골든 근거만 주고 잰다. **사다리 밖 · 상한 측정**

> 논문 §3.1: *"conditioning MLLMs only on … gold evidence … evaluating QA accuracy
> **without retrieval errors**"*

🔴 **우리 사다리 `A0`~`A8` 은 전부 "검색+생성" 합성 성능이다.** 검색을 완벽히 고정한 상태의
**생성 능력을 잰 적이 없다.** 그래서 `A10`·`A11`·`A12` 는 셋 다 *"생성이 문제다"* 를
**가정**하고 서 있다. `ORACLE` 이 그 가정을 검증한다.

| | |
|---|---|
| **구성** | `A8` 에서 검색을 건너뛰고 **골든 문서만** 근거로 넣는다. 재료가 이미 있다 — `report.json` 의 `golden` · `golden_evidence_all` · `golden_rank` |
| **읽는 법** | `Δ(A8 → ORACLE)` = **검색이 아직 못 가져온 몫** · `ORACLE` 의 잔여 오답 = **순수 생성 실패** |
| **왜 먼저** | 잔여 8건이 `GENERATION` 인데 그게 *진짜 생성 실패*인지 **근거가 부족해서 생긴 하류 증상**인지 지금 못 가른다. `L2` 의 서명(근거 112/118 동일, 정답 11건 적음)을 정면으로 가른다 |
| **비용** | 88문항 × 1회 ≈ **1,300원** |
| **G1** | ✅ 안전 |
| 🔴 **금지** | **제출 구성이 될 수 없다** — 평가 시점에 골든이 없다. **순수 진단용**이고, 게이트·제안서에 "성적"으로 인용하면 자기 성적표를 부풀리는 것이다. `상한` 으로만 적는다 |
| 🔴 **경계** | `heldout` 의 골든은 **건드리지 않는다.** 그리드 72 + 회귀 10 + 밸류체인 12 만 |

### ★ `A8-lean` — 프롬프트 규칙 다이어트. **attention 수치가 겨냥을 준다**

논문 Figure 2 (zero-shot 전 표본 평균 주의 배분):

```
system 36.9%  ·  output 34.5%  ·  text evidence 14.0%  ·  question 10.8%  ·  image 4.4%
```

**시스템 프롬프트가 근거보다 2.6배 많은 주의를 받는다.** HCX 는 attention 을 못 보지만
**대리 실험은 된다** — 규칙을 줄이고 정답률을 재는 것이다.

🔴 **우리에게 실측 겨냥이 있다**: `Q-018` 이 정확히 *"규칙 8·9 가 답변 어휘를
`계약금액`→`공시 금액` 으로 바꿔 검증 게이트를 닫았다"* 다(`Phase 2 ⑤`). **규칙이 근거를
밀어낸 사례**이고, 보류 `I-2` 와 같은 뿌리다.

- **후보**: 어휘를 바꾼 것으로 **실측된 규칙만** (착수 시 `prompts._BASE_RULES` 를 읽고 확정)
- 🔴 **규칙 1~4(근거만 사용 · 거절 문구 · 인용 형식 · 정정본 명시)는 건드리지 않는다** —
  넷 다 **채점 항목에 직결**된다. 빼면 다른 지표가 무너진다
- **비용** 88문항 × 1회 ≈ 1,300원 · **G1** ✅

### ★ judge 재현 편차를 **σ 로** 낸다 (arm 아님 · 측정 신뢰도)

논문은 GPT-4o judge 를 **3회 돌려 표준편차를 표로 보고**한다(Table 6·7·8).
🔴 **우리는 judge 편차를 안 잰다.** 밸류체인이 `6→5→6` 으로 흔들린 것이 정확히 이것이고,
지금은 *"재측정마다 ±1문항"* 을 **추정으로** 적고 있다.

- **방법**: judge 만 3회 재실행(생성은 캐시 적중) → 문항별 판정 분산 · arm별 σ
- **비용**: judge 78,565 토큰 × 2회 ≈ **1,100원**
- **얻는 것**: `Δ` 가 **σ 안인지 밖인지** 판정 가능해진다. `A10`~`A12` 의 Δ 가 1~2문항 규모라
  **σ 를 모르면 채택 판정을 못 한다**

### 논거만 보강되는 것 셋 (새 arm 아님)

| | |
|---|---|
| **`A11` cross-evidence** | 논문 Table 1: `single-text 92.76` vs `multi-text_img 56.26`, `multi-cross_para` 는 SFT 후 **−23.73 붕괴**. **"여러 근거를 결합하는 것이 구조적으로 어렵다"를 다른 논문이 독립 실측**했다 |
| **파인튜닝 불가가 손해가 아니다** | *"SFT yields mixed and inconsistent gains … **structural limitation**"*. **학습으로 안 되는 문제**이므로 프롬프트·근거 표현 개입(`A10`~`A12`·`A8-lean`)이 옳은 방향이다 |
| **마크다운 정규화가 옳았다** | 논문 Q2: **parsed text > page image**. `XML→마크다운` 선택의 독립 근거이고, `T3 문단 나누기`가 성능 축이라는 뒷받침이다 |

### 🔴 순서 — 셋을 지킨다

```
R1   ORACLE (1,300원) + judge σ (1,100원)     ← 전제와 잡음 폭을 먼저 확정
      │  ORACLE 이 "검색 몫" 으로 나오면 아래 넷을 보류하고 검색으로 돌아간다
      ↓
R2   Phase 2 잔여 실패 (처방이 인라인으로 이미 있다)
      │  겨냥이 겹친다 — Q-018 · Q-044 · Q-098 · Q-101
      ↓
R2+  A10 · A11 · A12 · A8-lean  ← 처방으로 안 닫힌 문항만
```

**① `ORACLE` 이 앞이다.** 생성 arm 넷의 전제를 검증하고, 검증 없이 세우면 **검색 문제를
생성 arm 으로 고치려는 것**이 된다.

**② `judge σ` 도 앞이다.** `A10`~`A12` 의 Δ 가 **1~2문항 규모**로 예상되는데 **σ 를 모르면
채택 판정을 못 한다.** 지금 우리는 *"±1문항 흔들림"* 을 추정으로 적고 있다.

**③ `Phase 2` 처방이 생성 arm 보다 앞이다.** 겨냥이 겹치므로(`Q-018`·`Q-044`·`Q-098`·`Q-101`)
**순서를 바꾸면 어느 쪽이 고쳤는지 못 가린다.**

## 🔴 v3 에는 heldout 이 없다

`heldout.jsonl` 은 **2회 소진**(v1 `A6` · v2 `A8`)이고 3회째는
`scripts/ablation.py::assert_heldout_unused` 가 세 겹으로 막는다. **v3 의 일반화 측정은

## 🔴 E — 게이트 첫 항목이 CLOVA 경로에서는 성립하지 않는다


오른다 → **생성 문제이고 처방은 T1·T2 가 아니라 프롬프트다.** 어느 쪽이든 T5 는 다음
라운드의 겨냥을 정한다.

## 비용과 자리

```
T5-a + T5-b     읽기 전용 · LLM 0회 · 크레딧 0원 · 우리 토큰 ~150k (약 2%)
재측정          없음 — 이미 산 산출물을 읽는다
의존            없음. T0 과 병렬. T0 이 CLOVA API 를 전부 취소해도 T5 는 산다
```

🔴 **예산 사다리 `~10%` 구간에 이것을 넣어라.** 크레딧 0원이고, 제안서에서 가장 강한 서사의
**마지막 칸**을 채운다.

**제안서에 쓸 서사는 "GraphRAG 를 기각했다" 가 아니다** — 그렇게 쓰면 우리가 실제로 번 것을
우리가 지우는 것이다. 쓸 문장은 이것이다:

> 논문이 전제한 엣지 정의(기업—기업)는 우리 코퍼스에서 완결도 1.2% 로 **기각됐다.**
> 노드·엣지를 코퍼스에 맞게 **재정의**했고 — 2부 그래프 · 정정 550엣지 · 관련공시 1,267엣지 ·
> n-ary 이벤트 노드 — 그 재정의가 **사다리 상승폭의 대부분**을 만들었다
> (`L1 −9.7%p` · `L2 −15.3%p` · `A1→A1b +41.7%p`, 두 판 재현).
> 남은 한 엣지(계약상대 2-hop)는 근거 완결성에서 재현 가능하게 이기지만
> (28/46 vs 23/46) 정답률로는 확정되지 않아 **판정을 유보한다.**

**T5 는 마지막 문장의 "유보" 를 채택 또는 기각으로 바꾼다.** 닫힌 판정이 유보보다 강하다.
