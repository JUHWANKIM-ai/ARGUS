# CLOVA 1급 API 재고 계획 — 우리가 손으로 만든 것들을 플랫폼이 이미 준다

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 로 태스크
> 단위 실행. 각 태스크는 **측정 후 채택**이고, 기각도 결과다.

**Goal:** CLOVA Studio 가 1급 API 로 제공하는 `리랭커` · `라우터` · `문단 나누기` ·
`RAG Reasoning` 을 우리 자체 구현과 **실측 대조**해 채택/기각을 판정한다.

**Architecture:** 기존 ablation 하네스에 arm 을 얹는다. 각 API 를 **독립 arm** 으로 두어
기각 시 곡선이 그대로 성립하게 한다 (A3 가 이미 그렇게 설계돼 있다).

**Tech Stack:** CLOVA Studio API · 기존 `scripts/ablation.py` · `RequestCache`

## 왜 이 계획이 생겼나

2026-08-11, 사용량 대시보드의 모델 구분을 보고 발견했다. 우리가 부른 엔드포인트는 둘뿐이다:

```
/testapp/v3/chat-completions/HCX-005     생성
/v1/api-tools/embedding/v2               임베딩 (A2 — 실측 기각)
```

그런데 대시보드는 `리랭커` · `라우터` · `문단 나누기` · `RAG Reasoning` · `요약` 도
1급 API 로 낸다. **넷은 우리가 손으로 만들었고, 하나(리랭커)는 아예 없다.**

`05-reranker.md §E-2` 의 후보 표가 **전부 외부 모델**(BGE·MiniLM)이었고, 그래서 §E-1 의
규정 리스크("외 LLM 사용 시 평가대상에서 제외")가 Phase 전체를 막았다.
**그 리스크는 CLOVA 자체 리랭커에는 걸리지 않는다** — 같은 플랫폼이다.

즉 **규정 때문에 못 한 것이 아니라, 규정에 안 걸리는 경로를 후보에 넣지 않아서 못 했다.**

## 🔴 T0: 먼저 잴 대상이 있는지 확인한다 — **이 태스크가 나머지를 취소할 수 있다**

**착수 전 필수.** `05 §E-4` 가 재검토 문턱 3축을 재서 **전부 0** 이다:

| 재검토 조건 | 값 | 출처 |
|---|---|---|
| 신규 6섹터 `RETRIEVAL` 실패 (문턱 3) | **0건** | `v2/A8/report.json > new_sector_retrieval.n` |
| A3 겨냥 문항 | **0건** | Q-094 가 리랭커 없이 정답이 됐다 |
| 그리드 `RANKING` 실패 | **0건** | `failure_histogram_grid` |

**리랭커를 넣어도 Δ 를 잴 대상이 없다.** Q-094 의 이력이 경고다 — "골든이 rank 8 이라 리랭커가
필요하다" 는 진단이 **틀렸고**, 실제 원인은 다문서 질의 분해였다. 순위를 재정렬해도 없는
문서는 안 올라온다.

**T0 의 산출**: 각 API 별로 **겨냥할 실패가 실제로 있는지** 산출물에서 세라.

| API | 겨냥 후보 | 확인할 산출물 |
|---|---|---|
| 리랭커 | `RANKING/*` 실패 · MRR·P@1 손실 | `failure_histogram_grid` · `recall_v2.json` |
| 라우터 | 라우팅 오탐/미탐 · `ROUTING` 실패 | 이번 라운드 오탐 6종 · `A1` 의 `ROUTING` 39건 |
| 문단 나누기 | 표 밖 `<P>` 단락 · 섹션 경계 실패 | `01-eda` 의 표 밖 116/21건 |
| RAG Reasoning | `REASONING` 실패 · 사다리 스텁 | 현재 Q-023·Q-093 |

**겨냥이 0 인 API 는 그 태스크를 취소하고 그 사실을 기록한다.** "잴 대상이 사라졌다" 는
"못 했다" 와 다르고, 그것을 기술제안서에 그렇게 적는다.

## T1: 라우터 — 겨냥이 가장 확실하다

**우리 라우터는 정규식이고 이번 라운드에 오탐 6종이 실측됐다.**

```
삼성전자의 발주처는?           `발주` 가 `발주처` 의 접두
수주 기업은 삼성전자. 발주처는?  canonical() 이 마침표를 지워 문장 경계가 사라진다
HMM, 발주처 현황               쉼표
```

그리고 `A1`(문서군 통합 색인)의 `ROUTING` 실패가 **39건**이다(A0 은 0건). 그것이
`A0→A1` 이 **−8.3%p** 인 기전이다.

**Files:** `src/argus/agent/router.py` (수정 금지 — 대조만) · 새 `src/argus/agent/router_clova.py` ·
`tests/test_router_clova.py` · `src/argus/ablation.py`(arm 플래그)

## T4: RAG Reasoning — 마지막이다

우리 ReAct 사다리(`plan_hops` + 제동 8종)를 대신할 수 있는지. **겨냥은 `REASONING` 실패
2건**(Q-023 · Q-093)이고 둘 다 이미 처방이 소진됐거나 정직한 손실이다.

🔴 **G1 경계가 여기서 가장 예민하다** — RAG Reasoning 이 답변 문장을 만들면 "최종 답변 생성"
에 다른 모델이 끼는 것이다. **근거 선택·충분성 판정까지만** 쓸 수 있는지 API 문서로 먼저
확인하고, 애매하면 **디스코드에 묻고 착수하지 않는다.**

- [ ] **Step 1**: API 가 반환하는 것이 근거인지 답변인지 문서로 확정
- [ ] **Step 2**: 답변을 만들면 → **G1 위반 위험으로 기각**하고 그 판단을 기록
- [ ] **Step 3**: 근거만이면 사다리와 대조

## 순서와 이유

```
T0  겨냥 확인          ← 이것이 T1~T4 중 일부를 취소할 수 있다
T1  라우터             겨냥이 가장 확실 (오탐 6종 실측 + ROUTING 39건)

```

**T1·T2 는 한 라운드에 묶어도 된다**(둘 다 검색 층, 색인 불변). **T3 는 반드시 분리**한다.
