## 1. 🔴 먼저 밝혀진 사실 — 결정적 줄은 정답을 냈는데 모델이 안 썼다

계획서를 쓰기 전에 `Q-115` 의 근거와 흔적을 열었다. **진단이 바뀌었다.**

오픈이슈 v2 §4.2 는 이것을 *"계약 넷을 열거하고 둘만 합산한다"* 로 적었다. 근거를 보면
그보다 정확한 말이 있다.

```
근거의 결정적 줄
  [결정적 집계] 위 근거 2건의 금액 합계 (2025년 공시분 · 계약상대 현대자동차):
  106,796,802,000 + 1,652,800,000,000 = **1,759,596,802,000원**
  (이 값은 시스템이 위 근거의 금액 필드에서 직접 계산한 것이다.
   답변의 해당 수치는 이 값을 그대로 쓰고 다시 계산하지 않는다.)

답변
  1. 현대오토에버 — hCloud 125,514,000,000 · 차세대ERP 106,796,802,000
  2. 현대글로비스 — 해상운송 1,652,800,000,000 · 해상운송 1,345,900,000,000
  합계: 125,514,000,000 + 106,796,802,000 + 1,652,800,000,000 + 1,345,900,000,000
        = **1,759,596,802,000원**
```

**총액은 우리 줄에서 그대로 베꼈고 가산 항목은 자기가 다시 열거했다.** 우리 줄은 가산
항목이 둘이라고 명시했는데 답변은 넷을 늘어놓았다. 둘 사이에 아무 연결이 없다.

**왜 그런가.** 결정적 집계 줄은 **총액과 두 피가수만** 싣는다. *어느 계약이 그 둘인지*
(계약명·접수번호)는 안 싣는다. 모델은 근거 블록 다섯을 보고 「2025년 · 계약상대
현대자동차」 조건을 스스로 다시 적용해야 했고, 틀렸다.

같은 모양이 `Q-110` 에도 있다.

```
[결정적 조회] 한국수력원자력(주) 를 계약상대로 공시한 상장사는 6곳이다:
대우건설 · 두산에너빌리티 · 두산퓨얼셀 · 우리기술 · 한전기술 · 현대건설
```

**회사명만 있고 접수번호도 금액도 없다.** 그래서 답변이 항목마다 근거를 못 달고
(v2 §4.1), 항목별 금액을 못 적는다(v2 §5.2 「열거 항목별 금액 미기재」 2건).

🔴 **재생성은 이미 돌고 있고 이미 버려진다.** `Q-115` 3회 흔적이 모두 같다.

```
verify regen=1 reasons=amount: 답변 1,345,900,000,000원 vs 재계산 890,200,000,000
                kinds_after=calculation,provenance  kept=original
```

실패 종류가 그대로라 `_keeps_regenerated` 가 원본을 지킨다. **판단은 맞다** — 안 나아진
답을 채택하면 결함을 결함으로 바꾸는 것이다. 그리고 `regenerate_partial` 을 켜도 안 된다.
후집합이 전집합의 진부분집합이 아니다.

`Q-113` 은 반대 증거를 준다 — r1 은 `kinds_after=- kept=regenerated` 로 **재생성이 성공해
채택됐고**, r2·r3 는 재생성이 오히려 종류를 늘려 버려졌다. **생성 쪽 처방은 3회 중 1회만
값을 한다.**

> SWE-Lancer 가 잰 것이 이것이다 — 판단 44.9% vs 생성 26.2%
> ([multi_agent.md §3](../../../paper/multi_agent/multi_agent.md)). 생성을 한 번 더 시켜서
> 고치는 길은 우리 실측에서도 1/3 이다. **결정적으로 고칠 수 있는 것은 결정적으로 고친다.**

## 4. 처방

### P-A · 결정적 줄이 항목 명세를 낸다 (`Q-115` `Q-110`)

**근거** Graph of Thoughts aggregation. **겨냥** `Q-115`(3/3) · `Q-110`(3/3) ·
v2 §5.2 「열거 항목별 금액 미기재」 2건.

**무엇을 바꾸나.** 두 줄이 항목 신원을 나르게 한다.

```
지금  [결정적 집계] 위 근거 2건의 금액 합계 (…): 106,796,802,000 + 1,652,800,000,000 = 1,759,596,802,000원
바꿈  [결정적 집계] 위 근거 2건의 금액 합계 (…) = 1,759,596,802,000원
        · 차세대 ERP 아태 및 유럽 롤인 프로젝트 계약  106,796,802,000원  (20251128800125)
        · 완성차 해상운송계약                        1,652,800,000,000원  (20250117800487)
      🔴 이 둘만 가산 대상이다. 다른 근거 블록은 조건에 안 맞아 제외됐다.

지금  [결정적 조회] 한국수력원자력(주) 를 계약상대로 공시한 상장사는 6곳이다: 대우건설 · …
바꿈  [결정적 조회] 한국수력원자력(주) 를 계약상대로 공시한 상장사는 6곳이다
        · 두산에너빌리티  신한울 3,4호기 원자로설비  2,338,117,950,000원  (20240329800342)
        · 한전기술        가동원전 계통설계 기술용역     25,605,030,000원  (20230727800471)
        · …
```

**왜 이것이 처방인가.** GoT 의 논지는 *"병합 연산이 없으면 모델이 여러 갈래를 못 합친다"*
다. 우리는 병합을 **이미 결정적으로 했다.** 그런데 결과만 보여 주고 **무엇을 병합했는지는
안 보여 준다.** 모델은 조건 적용을 처음부터 다시 해야 하고, `Q-115` 에서 틀렸다.

**코드 자리** `src/argus/agent/aggregate.py` — `_sum_rows`(893) · `line`(947) ·
`counterparty_branch`(504) · `roster_line` 플래그가 만드는 줄.

**🔴 위험** 결정적 줄의 문면이 바뀌면 **그 줄이 실리는 모든 문항의 답변이 바뀐다.**
`aggregate_line` · `roster_line` · `substitute_aggregate` 는 `A56` 에서 켜져 있고 112문항
중 상당수에 닿는다. **가장 위험한 처방이고 그래서 첫 파도에 둔다** — 재고 기각할 시간이
있어야 한다.

**측정 전에 답할 것.** 이 줄이 몇 문항에 실리는가. 그 수를 모르면 위험을 모른다.

### P-B · 정정 체인은 짝으로 인용한다 (5문항)

**근거** Relink distractor 랭커의 **query-driven** 성질. **겨냥** `Q-054` `Q-068` `Q-082`
`Q-093` `Q-094` — 다섯 다 *"무엇이 왜 정정됐는지"* 를 묻고 다섯 다 정정본만 인용한다.

**왜 `cite_used` 가 못 닿나.** 유일성 규칙 때문이다 — *"답변이 쓴 수가 그 블록에만
유일할 때"* 붙인다. 원공시와 정정본은 **같은 수를 담고 있어** 정정 체인 안에서 유일성이
성립하지 않는다. 규칙은 옳고 적용 범위가 문제다.

**무엇을 바꾸나.** 유일성 규칙을 **그대로 두고** 예외를 하나 만든다 — 질문이 정정
대조를 요구하고 인용된 접수번호가 근거 안에 체인 형제를 가질 때, **그 형제를 짝으로
붙인다.**

질의 판정은 새로 만들지 않는다. `critic._CHAIN_ASK` 가 이미 *"질문이 정정·해지 결과를
묻는가"* 를 가르고 있다(`critic.py:1389` 의 `wants_outcome` 이 그것을 쓴다). **같은 검사를
두 곳에 만들면 한쪽만 고쳐지는 것이 이 저장소의 반복 실패다** — 그 술어를 가져다 쓴다.

**코드 자리** `src/argus/ablation.py` — `_cite_missing_used` 옆에 `_cite_chain_pair`.
새 플래그 `cite_chain_pair`.

**🔴 위험** 접수번호를 **더 붙이는** 변경이다. `MAX_CITATIONS_USED = 8` 상한이 있다.
§4.4 가 바로 이 함정에 빠졌다 — **상한이 있는 창에 더하는 것은 밀어내는 것이다.**
측정 전에 「지금 몇 개를 붙이고 있는가」를 전수로 세어 상한 여유를 확인한다.

### P-C · 거절 판정에 외부 신호를 곱한다 (`Q-053`)

**근거** Self-Consistency 의 calibration 부재. **겨냥** `Q-053`(3/3, 두 측도 모두).

**무엇이 일어나나.** 답변이 *"…찾을 수 없으며"* 라 적었고 그 어구가 `_CITE_REFUSAL` 에
있어 표기 부착이 **거절로 판정해 아무것도 안 붙인다.** 실제로는 답할 수 있는 문항이고
답도 맞다 — *"내부통제에 관한 사항은 분기보고서에 기재하지 않는다"* 가 정답이다.

**왜 어구 목록을 늘리지 않나.** v4 에서 이미 측정 후 기각했다 —
*"모델이 거절하는 낱말은 끝이 없다."* 그리고 논문이 준 교훈이 정확히 이것이다:
**모델 출력만으로 판정하지 말고 외부 신호를 쓰라.**

**무엇을 바꾸나.** 거절 판정을 **곱집합**으로 만든다.

```
지금   거절이다  ⟸  답변 문면에 거절 어구가 있다
바꿈   거절이다  ⟸  답변 문면에 거절 어구가 있다
                  AND 질문이 지목한 문서·섹션이 근거에 실리지 않았다
```

`Q-053` 은 근거에 그 스텁 섹션이 실려 있다. 그래서 거절이 아니고, 표기가 붙는다.

**코드 자리** `src/argus/ablation.py` — `attach_citation` 의 거절 분기. 새 플래그
`refusal_needs_gap`.

**위험이 가장 낮다.** 저장된 답변 726개에 대해 **호출 없이 전수 증명**할 수 있다 —
`citation_note_fix` 를 채점 중립으로 증명한 것과 같은 방법이다. 첫 파도에 같이 재고,
영향받는 문항이 `Q-053` 하나임을 확인한 뒤 채택한다.

## 5. 순서와 파도

```
W1  측정 준비 — 호출 0회
    · 결정적 줄이 몇 문항에 실리는가 (P-A 의 위험 크기)
    · 지금 붙는 접수번호 수의 분포와 MAX_CITATIONS_USED 여유 (P-B 의 위험 크기)
    · 저장된 답변 726개로 refusal_needs_gap 전수 증명 (P-C)

W2  P-C 채택 판정      가장 싸고 위험이 가장 낮다. 로컬 1회 + 3회
W3  P-B 채택 판정      한 기계에 다섯 문항. 로컬 1회 → 퇴행 0 이면 3회
W4  P-A 채택 판정      가장 위험하다. 로컬 1회 → 퇴행 0 이면 3회

W5  합본 3회 + 미공개셋 1회
```

**W1 을 건너뛰지 않는다.** P-A 와 P-B 의 위험 크기를 모르는 상태에서 스위치를 세우면
§4.4 의 실패를 반복한다 — *"덧붙이는 변경이라 아무것도 빼지 않는다"* 고 적고 나서
상한에 밀려 근거를 잃었다.
