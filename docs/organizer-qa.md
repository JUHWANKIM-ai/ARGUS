### 🔴 #2 — 타임아웃 300초는 **게이트 E 의 지연 문턱을 없앤다**

`05-reranker.md` 게이트 E 의 마지막 항목이 *"Δ P@1 이 **지연 증가**를 정당화하는가"* 였다.
우리 실측 지연은 `A0` 3.73초 수준이고 **300초는 그보다 두 자릿수 넉넉하다.**
**리랭커 한 단계·RAG Reasoning 한 단계를 더 얹어도 타임아웃은 제약이 아니다.**

→ **게이트 E 의 판정 기준을 "지연 대비 이득" 에서 "정답률·근거 대비 크레딧" 으로 옮긴다.**
→ `A4` ReAct 사다리의 스텝 상한도 지연 때문에 묶을 이유가 없다. **묶는 이유는 크레딧과
과잉탐색(`pipeline.py:80` 의 제동 셋)뿐이다** — 그 사실을 명시한다.

### 🔴 #3 — 재시도 2회는 **실패를 3배로 만든다**

에러를 던지면 같은 질의가 **최대 3회** 들어온다.

- **결정적 실패**(우리 버그): `RequestCache` 가 프롬프트 SHA256 로 적중하므로 크레딧은 안 늘지만 **오답이 3번 확정된다**.
- 🔴 **비결정적 실패**(타임아웃·상류 5xx): 캐시 미적중이라 **크레딧이 3배**다.
- 🔴 **설계 결론: 답할 수 없을 때 5xx 를 던지면 안 된다.** `A7` 거절 게이트가
  **200 + 정보한계 응답**을 내야 하고, 그것이 #9 의 정보한계대응과 같은 축이다.
  → **착수 전 확인 항목**: `api/server.py` 가 파이프라인 예외를 5xx 로 흘리는지,
  아니면 정보한계 응답으로 감싸는지. (`pipeline.upstream_failure` 의 `retryable` 이 있으니
  분기는 존재한다 — 그것이 HTTP 상태로 어떻게 나가는지가 문제다.)

### 🔴 #6·#14 — 서버 비용 가정이 **최대 5배 차이 난다**

우리는 `docs/clova_payment.md` 에서 **480시간 전일 가동 = 44,160원**을 잡았다.
그런데 예시가 *"09:00 - 16:00 간"* 이다.

```

7h × 14일   98h × 92원 =   9,016원      ← 공지가 시간대를 한정하면
```

🔴 **그러나 지금 계획을 바꾸지 않는다.** ① 시간·기간이 **미확정**이고 ② *"정지 상태로

낮아졌으니, 공지가 오면 그때 시간요금제 + 자동 시작/정지를 검토한다.**
**전망에는 보수적으로 44,160원을 유지하고, 이 절을 근거로 남긴다.**

# 2차 공지 — 평가용 API End-point 규격 (2026-08-12)

**규격의 정본은 [CONVENTION.md §4](CONVENTION.md) 로 옮겼다.** 여기는 전사와 **영향**만 남긴다.

## 원문 요지 (전사)

- **구성**: 네이버클라우드 또는 개인 서버자원. 서버 환경은 자유이나 **Public 망 접근 가능 필수**.
  **End-point 주소는 `README.md` 에 명시(필수)**. 주최측이 GET 으로 비공개 평가질의 전송.
- **호출**: ① 팀당 **순차 1건씩**(동시 요청 없음) ② 문항당 타임아웃 **300초**
  ③ **타임아웃 또는 5xx 시 최대 2회 재시도**
- **요청**: `GET {end-point}/answer?question_id={ID}&question={질의}` · 경로 `/answer` 고정 ·
  **별도 헤더 없음(인증 헤더 포함)** · 접근 제어는 **주최측 발신 IP 허용** 방식
- **응답**: 5키 JSON · **모든 필드 string** · `application/json` · 길이 제한 없음
  (단 극단적으로 길면 초과분 미반영) · `retrieved_context` 의 문서 구분 태그는 **평가 대상 아님**
- **서버**: ① **HTTP 기본**, HTTPS 는 선택이며 **self-signed 무방** ② 포트 **80 / 443** 표준
  ③ **도메인 불필요 — 공인 IP 로 제출 가능** ④ 주최측 발신 IP 대역 추후 공지(화이트리스트 선택)
  ⑤ 운영 기간 **09-07~09-20 중 별도 공지 · 각 주제별 최대 1주** ⑥ 장애 재기동은 실격 아님
  ⑦ **개인 환경(노트북 등) + 터널링(`ngrok` 등) 자유** — 정적 도메인 URL 제출
- **예시**: `requests.get(URL, params=..., timeout=300)` / `curl -G --data-urlencode`

## 🔴 우리 영향 — 셋이 바뀐다

### ① HTTPS 미확정이 **해소**됐다

`CONVENTION` 이 네 곳에서 HTTPS 를 필수로 적고 있었고, `proposal/README.md §5` 의 미해결
2번이 *"주최 측 대안 공지 대기"* 였다. **HTTP 기본 · HTTPS 선택 · self-signed 무방 ·
도메인 불필요**로 확정됐다 → **`Global DNS`·`Certificate Manager` 를 다룰 필요가 없다.**
`deploy/README.md` 의 ACG 인바운드 `22·80·443` 은 그대로 유효하다.

### ② 서버 비용이 **절반 이하**로 준다

*"각 주제별 최대 **1주**를 넘기지 않도록"* — 우리는 평가기간을 **336h(2주)** 로 잡고 있었다.

```
종전 가정   평가 336h + 준비 8~12h            ≈ 32,000~35,000원
확정 상한   평가 168h(1주) + 준비 8~12h        ≈ 16,500~17,500원
시간대까지 한정되면 (예: 09~16시 × 7일 = 49h)  ≈  5,600원
```

🔴 **다만 전망은 168h 를 유지한다** — 정확한 일자·시간대가 미공지이고,
*"정지 상태로 평가기간 진입 = 전 문항 0점"* 이 여전히 최악 리스크다.

### ③ **서버를 아예 안 쓰는 경로**가 열렸다

*"개인용 환경(노트북 등) 구성 시 … 터널링 서비스(`ngrok` 등)를 자유롭게 활용"*.

| | 클라우드 서버 | 노트북 + 터널링 |
|---|---|---|
| 크레딧 | **16,500~17,500원** | **0원** |
| 위험 | 낮음 (관리형) | 🔴 전원·네트워크·수면 모드 — **1주 상시** |
| 완화 | — | 재기동이 실격 아니므로 치명도는 낮아졌다 (#6) |
| 판정 | 🔴 **사용자 결정 사항** | 크레딧 여유가 78%(추정 최종 22%)라 **비용이 병목이 아니다** |

**권고: 클라우드 서버 유지.** 크레딧은 남고, 1주 상시 가동에서 노트북 위험이 크다.
