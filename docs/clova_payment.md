# CLOVA 크레딧 운용 방침

HyperCLOVA X / NCP 크레딧은 **총 30만원, 유효기간 2026-09-30, 초과분은 자체 부담**이다
([CONVENTION §8](CONVENTION.md)). 이 문서는 그 예산 안에서 과제를 끝내기 위한 방침이다.

예산 계산은 [notebooks/clova_budget.ipynb](../notebooks/clova_budget.ipynb)에서 수치로 돌린다.

> 같은 돈을 아끼면서 규정 리스크와 일정 리스크를 둘 다 피한다.

## 2. "다른 모델로 개발하고 클로바로 테스트" 는 하지 않는다

비용을 아끼려는 판단은 맞지만, 이 방법은 두 가지가 깨진다.

### 2.1 규정 — 선은 "과정"이 아니라 "산출물"에 있다

| 용도 | 다른 모델 | 판단 근거 |
|---|---|---|
| 파이프라인 로직 검증 (라우터 분기, 루프 동작) | 무해 | 산출물이 남지 않음 |
| 코드 작성·설계 상담 | 무해 | 도구일 뿐 |
| **오프라인 인덱스 구축** (n-ary 팩트 추출, atomic fact 요약, 커뮤니티 요약) | **금지** | **추출 결과가 데이터로 실려 나간다** |

GraphRAG 계열에서 **인덱스는 곧 제품**이다. 외부 모델로 하이퍼엣지를 뽑아 그 그래프를 서빙하면
"LLM은 HyperCLOVA X만"([CONVENTION §2 G1](CONVENTION.md)) 조항을 우회한 것이 된다.
실격이 걸린 항목에서 회색지대를 밟을 이유가 없다.

**그리고 비용이 가장 큰 작업이 정확히 이 인덱싱이다.** 아끼고 싶은 지점과 대체하면 안 되는 지점이
겹친다 — 이것이 이 전략이 성립하지 않는 근본 이유다.

### 2.2 기술 — 프롬프트는 모델 간 이식되지 않는다

- **CoT는 창발 능력이다**([paper/base/base.md](../paper/base/base.md) §2). 외부 모델에서 잘 나오던
  사고연쇄가 HCX-005에서 스케일이 부족하면 *"유창하지만 비논리적인"* 추론이 되고,
  논문은 이 경우 **표준 프롬프팅보다 더 나빠진다**고 보고한다.
  평가 8지표에 「근거 기반(환각)」이 있어 그대로 감점된다.
- few-shot exemplar 선택, JSON 스키마 준수율, 한국어 처리 품질, function calling 지원,
  토크나이저(→ 비용 추정 전부 무효)가 모델별로 다르다.
- 결과적으로 **모델 고유 리스크 전부를 마감 직전으로 미루는 일정**이 된다.
  제출 마감 09-06 기준으로 가장 하면 안 되는 설계다.

## 3. 진짜 지렛대 — 서버 가동일

설명회 시뮬레이션 **"2개월에 15~16만원"은 인프라(서버) 비용**이었다. LLM 토큰이 아니다.
8월 내내 서버를 띄워두면 20만원 대부분이 서버로 나가고 토큰 예산이 남지 않는다.

> **개발 기간에는 NCP 서버를 켜두지 않는다.**

설명회에서 명시했다 — *"개발은 여러분 PC나 데스크탑에서 해도 상관없는데 배포는 반드시
공인 IP가 있는 서버"*. 서버가 반드시 살아 있어야 하는 구간은 **09-07~09-20 평가기간**뿐이다
([CONVENTION §1](CONVENTION.md)).

| 구간 | 서버 | 비고 |
|---|---|---|
| **8월 개발** | **정지 유지** (로컬 개발) | 2026-08-08 정지 완료. 디스크 요금만 발생 |
| 8월 말 배포 리허설 | **시작** (수일) | 엔드포인트·HTTPS·방화벽 검증 |
| 09-06 제출 | 켬 | 이후 코드 변경은 실격 |
| **09-07 ~ 09-20** | **필수 상시 가동** | 평가기간. 절대 죽으면 안 됨 |
| 09-20 이후 | **반납** | 서버 + 공인 IP 각각 반납 |

리허설 구간을 너무 줄이지는 말 것 — 평가기간에 서버가 죽으면 크레딧을 아낀 의미가 없다.

> 🔴 **09-07 이전에 서버를 반드시 `시작`할 것.** 정지 상태로 평가기간에 들어가면
> 모든 질의가 0점이다. 캘린더 알림 필수.

### 3.1 요금제 — 시간 요금제로 확정 (NCP 콘솔 실측, 2026-08-08)

`c2-g3a` (2 vCPU / 4 GB, **OS 제외**) 기준:

| 항목 | 값 |
|---|---|
| 시간 요금제 | **92원 / 시간** |
| 월요금제 | **66,240원 / 월** |
| 공인 IP | 4,032원 / 월 (**보유 기간 과금** — 미사용 시 반납) |

```
손익분기 = 66,240 ÷ 92 = 720시간 = 정확히 30일
```

**월요금제에 할인이 전혀 없다.** 24시간 × 30일을 꽉 채워야 겨우 본전이므로,
그보다 덜 쓰는 우리는 **시간 요금제가 무조건 유리**하다.

| 가동 구간 | 시간 | 시간 요금제 | 월요금제 |
|---|---|---|---|
| 평가기간만 09-07~09-20 | 336h | **30,912** | 66,240 |
| + 앞뒤 여유 09-05~09-21 | 408h | **37,536** | 66,240 |
| + 8월 말 리허설 3일 | 480h | **44,160** | 66,240 |
| 8월부터 계속 (46일) | 1,104h | 101,568 | 132,480 |

**목표: 총 480시간 이내 ≈ 44,160원.** 8월부터 월요금제로 켜두는 최악 대비 **88,320원 절약**.

> **OS 선택이 곧 돈이다.** 92원·66,240원 모두 (OS 제외)다. **Ubuntu / Rocky Linux**를 쓸 것.
> Windows Server는 라이선스가 시간당 추가되어 위 계산이 전부 무효가 된다.

### 3.1.1 정지 vs 반납 — 과금 규칙 (콘솔 안내문으로 확정, 2026-08-08)

콘솔 정지 안내창 원문:

> "서버를 정지한 후에도 **표준 요금이 청구**됩니다. 요금 청구를 원하지 않을 경우 서버를 반납해 주십시오."
> "서버 정지 시 표준 요금이 청구되나 Compact, Standard, CPU Intensive, Standard [G2,G3],
> **High CPU [G2,G3]**, High Memory [G2,G3] 타입은 **운영체제 설치를 위한 기본 디스크 요금**[만] 청구됩니다."
> "서버 정지 후에도 **공인 IP** … 이용 요금이 청구되므로 … 이용 계약을 해지해 주십시오."
> "요금을 할인 받는 서버는 1회 정지 시 최대 90일, 12개월 내 최대 180일만 정지 가능합니다."

**우리 서버 `c2-g3a`는 세대 `G3` · 스펙 `High-CPU` 이므로 면제 대상이다.**

| 리소스 | 정지 시 | 반납 시 |
|---|---|---|
| 서버 시간요금 92원/h | ✅ **청구 안 됨** (High CPU G3 면제) | ✅ 안 됨 |
| 기본 스토리지 20GB (CB1) | ❌ **청구됨** (월 2천원 내외 추정) | ✅ 안 됨 |
| 공인 IP 4,032원/월 | ❌ 청구됨 → **별도 반납 필요** | ✅ 반납 시 안 됨 |

> **공인 IP는 서버와 별개 리소스다.** 서버를 정지·반납해도 IP를 따로 반납하지 않으면 계속 과금된다.
> `Server > 공인 IP` 메뉴에서 별도로 반납할 것.

**현재 상태 (2026-08-08 결정)** — **서버 정지 + 공인 IP 반납.**
서버 시간요금과 IP 요금은 멈췄고 디스크 요금만 발생한다(24일 기준 약 1,500~2,000원).
반납 대신 정지를 택한 이유는 8월 말 리허설 때 `시작` 버튼 하나로 부활하기 때문이다.
정지 제한(1회 90일)에도 걸리지 않는다.

VPC·Subnet·**인증키 `argus`**·ACG·로컬 `~/.ssh/config`의 `argus` 항목은 어느 경우든 남는다.

**검증에 쓴 실제 비용**: 생성 14:06 → 구동 14:08 → 정지, 약 40분 = **60~70원**.

## 4. 예산 방정식

```
총비용 =  (질문당 호출 수 × 단가 × 평가 질의 수)      ← 평가 추론
        + (벌크 인덱싱 토큰 × 단가)                    ← 오프라인 인덱싱
        + (개발셋 질의 × 반복 횟수 × 질문당 호출 × 단가) ← 개발
        + (서버 가동일 × 일단가)                        ← 인프라
        ≤ 300,000원
```

**실측이 필요한 미지수 4개** (전부 [notebooks/clova_budget.ipynb](../notebooks/clova_budget.ipynb)의 CONFIG에 있다)

| 미지수 | 확인 방법 |
|---|---|
| HCX-005 입력/출력 1K 토큰당 단가 | NCP 요금 페이지 + 실제 호출 1회의 `usage` 응답 |
| 한국어 문자/토큰 비율 | CLOVA Studio **토큰 계산기**에 공시 원문 샘플 투입 |
| 서버 일단가 | NCP 요금 계산기 (2 vCPU / 4 GB / 20 GB / 공인 IP) |
| 평가 질의 수 | **비공개**([CONVENTION §4](CONVENTION.md)) → 범위로 가정하고 민감도 분석 |

## 5. 비용 억제 순서

낮은 것부터 조인다. 위 항목이 항상 먼저다.

1. **서버 가동일** (§3) — 규정·품질에 영향 0, 절약폭 최대. **가장 먼저 조인다.**
2. **LLM-free 작업 선행** — 아래 항목은 **LLM 호출 0회**다
   ([paper/idea/idea.md](../paper/idea/idea.md) §5). 전체 공수의 대부분이 여기다.
   - XML 파싱 → 마크다운 정규화, 목차 기반 섹션 청킹
   - `manifest.jsonl` · `universe.csv` 메타데이터 프리필터
   - 정정공시 체인 역추적, 동의어 사전(universe에서 무료)
   - BM25 / 임베딩 / PPR / PCST / reranker — ToG-2는 프루닝에 BM25도 충분하다고 보고
   - PMI 공동출현 그래프
   - E2E 평가 하네스, API 서버 스켈레톤
3. **인덱싱 티어 축소** — 정기공시 680MB는 애초에 전량 추출 대상이 아니다.
   수시공시(exchange+major)는 **9MB뿐**인데 평가 예시 6개 중 4개를 커버한다.
   여기가 투자 대비 효과 최고 구간이다.
4. **질문당 호출 수 상한** — 대화형 멀티에이전트를 쓰지 않는 이유가 이것이다
   ([paper/multi_agent/multi_agent.md](../paper/multi_agent/multi_agent.md) §4).
   역할 분리된 결정적 파이프라인은 질문당 비용 상한이 계산된다.
5. **Self-Consistency의 k** — 비용이 k배다. Closed 질의 한정 + k 소값
   ([paper/base/base.md](../paper/base/base.md) §3).
6. **CoT 적용 범위** — 난이도 '하' 질의에는 이득이 없다(논문 보고). 라우터로 걸러낸다.

## 6. 개발 단계 비용 — 노트북이 뒤집은 부분

처음엔 "프롬프트 반복은 무시할 수준"이라고 봤는데, [예산 노트북](../notebooks/clova_budget.ipynb)을
돌려보니 **틀렸다.** 기본 가정(개발셋 30문항 × 40회 반복 × 질문당 6호출)에서
**개발 비용만 18만원**이 나와 예산의 60%를 먹는다. 인덱싱을 T1으로 줄여도 총액이 초과된다.

| 시나리오 | 인덱싱 | 개발 | 평가 | 서버 | 총액 |
|---|---|---|---|---|---|
| 전량 인덱싱 | 4,027,782 | 180,000 | 18,000 | 50,000 | **4,275,782** ✗ |
| periodic 제외 | 203,497 | 180,000 | 18,000 | 50,000 | **451,497** ✗ |
| T1만 | 67,675 | 180,000 | 18,000 | 50,000 | **315,675** ✗ |
| **T1 + 개발 절제**(반복 12회) | 67,675 | 54,000 | 18,000 | 45,000 | **184,675** ✓ |
| **위 + 호출수 6→4** | 67,675 | 36,000 | 12,000 | 45,000 | **160,675** ✓ |

(단가 미실측 가정값 기준 — 절대 금액이 아니라 **상대 비교**로 읽어라)

**수정된 결론**

- 호출 **1회**는 싸다. 그러나 `개발셋 × 반복 × 질문당 호출`이 곱셈이라 금방 커진다.
  → **반복 횟수를 명시적으로 고정하라.** 무한정 돌리면 인덱싱 예산을 개발이 먹는다.
- 여전히 유효한 부분: **벌크 인덱싱이 압도적으로 비싸다** —
  `periodic`이 전체 토큰의 **95%**(450M)이고 전량 인덱싱은 예산의 **13배**다.
- 따라서 원래 결론은 그대로다: "대체해서 아끼고 싶은 것"과 "대체하면 규정 위반인 것"이 겹친다.
  → **HCX를 첫날부터 쓴다. 단, 작은 고정 개발셋 + 반복 횟수 상한으로.**

**역산 결과 — 좋은 소식** ([노트북 §6](../notebooks/clova_budget.ipynb))
개발을 절제하면 인덱싱에 **약 16만원**이 남고, 이는
**exchange · major · holding 전량(T1+T2) LLM 추출을 감당**할 수 있는 규모다.
`idea.md`의 3단 차별화 전략이 예산 안에서 성립한다.
