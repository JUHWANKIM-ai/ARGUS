## C-2. n-ary 표현 — HyperGraphRAG

계약은 (기업, 상대, 금액, 기간, 비율)이 **한 덩어리**다. 이진 트리플로 쪼개면
`"2025년에 A사가 1조 이상 계약"` 같은 질의에서 조건이 분리돼 오답이 난다.

**이벤트 노드(= 하이퍼엣지) 로 표현한다.** 이미 정규화 레코드가 그 형태다.

```
[계약 이벤트]
  ├─ 주체     기업 (corp_code)
  ├─ 상대     counterparty
  ├─ 금액     amount / amount_type
  ├─ 기간     period_start ~ period_end
  ├─ 비율     ratio / ratio_base
  └─ 출처     rcept_no  ← 근거 인용의 앵커
```

> 🔴 **LLM 기반 n-ary 정밀 추출은 이 파이프라인에서 하지 않는다.**
> 규칙 기반 레코드로 그래프를 구성한다. LLM 추출은 크레딧·단가 확정 후 별도 계획.

## C-3. 대안 스키마 — 엣지 밀도가 낮을 때

기업-기업 엣지가 희소하면 **2부 그래프**로 축소한다.

```
기업 ──공시──▶ 이벤트 ──속성──▶ (금액·기간·상대)
 │
 └──섹터/업종──▶ 커뮤니티        ← universe 에서 무료로 얻는 계층
```

이 경우 GraphRAG 의 커뮤니티 요약(MSR)은 **Leiden 대신 universe 의 업종 8 > 섹터 20 > 기업 70**
계층을 그대로 쓴다. 알고리즘 비용 0.
