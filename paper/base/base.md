# base — 프롬프팅·에이전트 기초 5편

ARGUS(공시 Agent)가 서 있는 토대가 되는 논문들. 이 폴더의 5편은 **"모델을 학습시키지 않고
프롬프트만으로 능력을 끌어내는 법"** 의 계보다. HCX 베이스 모델을 학습시킬 수 없는
우리 제약([CONVENTION.md](../../docs/CONVENTION.md))에서 이 계보가 사실상 유일한 선택지다.

GraphRAG 계열 응용은 [../idea/idea.md](../idea/idea.md), 멀티에이전트는
[../multi_agent/multi_agent.md](../multi_agent/multi_agent.md) 참조.

## 1. GPT-3 — Language Models are Few-Shot Learners

- **문제** — 사전학습 후에도 태스크별로 수천~수만 건의 파인튜닝 데이터가 필요했다.
  인간은 예시 몇 개나 지시문만으로 새 과제를 한다.
- **방법** — 175B 파라미터 자기회귀 LM. **모든 태스크를 gradient 업데이트 없이**
  텍스트 상호작용(few-shot 데모)만으로 수행. zero/one/few-shot을 구분해 평가.
- **결과** — 번역·QA·cloze는 물론 단어 뒤섞기 복원, 3자리 산술 등 즉석 추론까지 수행.
  다만 few-shot이 여전히 약한 데이터셋과 웹 코퍼스 학습에 따른 방법론적 문제도 함께 보고.
- **ARGUS 시사점** — 이 논문이 **우리 접근의 전제**다. HCX 베이스 모델을 학습시킬 수 없다는
  제약은 곧 "few-shot ICL로만 승부한다"는 뜻이고, 그게 가능하다는 근거가 여기 있다.
  실무적으로는 **few-shot 예시 설계가 곧 성능**이라는 결론이 나온다 —
  공시 유형별(정기/주요사항/거래소/지분) 대표 예시를 골라 exemplar를 구성하는 작업에
  시간을 써야 한다. 동시에 이 논문은 **few-shot이 추론 태스크에 약하다**는 한계도 남겼고,
  그 한계를 다음 논문(CoT)이 푼다.

## 2. Chain-of-Thought Prompting

- **문제** — 모델 크기를 키워도 산술·상식·기호 추론은 안 됐다. rationale 학습은 고비용,
  일반 few-shot은 추론에서 무력.
- **방법** — few-shot 예시를 `<입력, 사고연쇄, 출력>` 삼중항으로 구성.
  손으로 쓴 **exemplar 8개**만 사용(프롬프트 엔지니어링 없이).
- **결과** — PaLM 540B + CoT 8-shot으로 GSM8K SOTA. verifier 붙인 파인튜닝 GPT-3도 상회.
  세 가지 핵심 관찰:
  1. **스케일 창발** — ~100B 미만에서는 효과 없음. 소형 모델은 "유창하지만 비논리적인"
     사고연쇄를 만들어 오히려 표준 프롬프팅보다 나빠진다.
  2. **어려운 문제일수록 이득이 크다** — GSM8K는 두 배 이상, 단일 스텝 SingleOp는 이득 없거나 음수.
  3. 해석 가능한 창을 제공해 **어디서 틀렸는지 디버깅**할 수 있다.
- **ARGUS 시사점** — 세 가지가 직결된다.
  - **`think_trace` 필드의 이론적 근거**가 이것이다. 평가 8지표의 「추론 논리성」을 채우는 수단.
  - **평가 질의 난이도 상/중/하 중 '상'에서 이득이 크고 '하'에서는 없다.**
    → 단순 조회 질의에 CoT를 붙이면 토큰만 쓰고 이득이 없다. **질의 유형 라우팅이 필요한 이유.**
  - ~~**리스크: HCX-005의 유효 스케일을 모른다.**~~ → **2026-08-08 실측 완료. 게이트 통과.**

**실측 결과** ([notebooks/clova_verify.ipynb](../../notebooks/clova_verify.ipynb) §5)

공시 도메인의 계산·비교 문항 6개(비중·증감률·합산·기간 산정)로 A/B 측정:

| 모드 | 정확도 | 평균 출력토큰 |
|---|---|---|
| Direct | 50.0% | 5 |
| **CoT** | **83.3%** | 147 |

**+33.3%p.** 논문이 경고한 "유창하지만 비논리적인 추론" 실패 모드는 관측되지 않았다.
**HCX-005에서 CoT는 유효하며 뼈대 재설계는 불필요하다.**

다만 두 가지가 따라온다.

1. **비용이 출력 토큰 30배**다. 난이도 '상' 질의에만 CoT를 태우는 라우팅이 그대로 유효하다.
2. **날짜 계산은 CoT로도 못 고친다** — 계약기간 산정("2025-07-24 ~ 2033-12-31 → 8년 5개월")을
   Direct·CoT **둘 다 오답**(9년 5개월). 공시에서 계약기간은 자주 나오므로
   **날짜·기간 연산은 LLM에서 빼고 결정적 함수로 처리**해야 한다.

## 3. Self-Consistency

- **문제** — CoT는 greedy 디코딩이라 한 경로가 틀리면 그대로 틀린다.
- **방법** — **sample-and-marginalize**: CoT 프롬프트로 **다양한 추론 경로 k개를 샘플링**하고,
  최종 답만 모아 **다수결**(marginalize out reasoning paths).
  학습·검증기·리랭커·주석 전부 불필요한 **완전 비지도 "self-ensemble"**.
- **결과** — GSM8K **+17.9%**, SVAMP +11.0%, AQuA +12.2%, StrategyQA +6.4%, ARC-c +3.9%.
  집계 방식 비교(PaLM-540B): 단순 다수결 74.4% ≈ 정규화 가중합 74.1% ≫ 비정규화 가중합 59.9%.
  → **가장 단순한 다수결로 충분하다.**
  부수 발견: 모델의 정규화 조건확률이 정답/오답 간 거의 차이가 없다
  = **LLM은 calibration이 안 돼 있다**(그래서 별도 리랭커를 학습하는 선행연구가 있었던 것).
- **ARGUS 시사점** — **양날의 검이고, 조건을 정확히 갈라야 한다.**
  - ✅ **적용 가능** — 학습 불필요, HCX API만으로 됨. 「정확성」 지표에 직접 기여.
  - ⚠️ **비용이 k배**다. 평가에서 응답 속도가 기준이 될 수 있으므로([CONVENTION §4](../../docs/CONVENTION.md))
    무조건 k를 키울 수 없다. 크레딧 20만원 제약도 있다.
  - ⚠️ **논문이 명시한 근본 한계: 최종 답이 고정 답변 집합에서 나올 때만 적용 가능하다.**
    우리 평가는 **Closed / Open-ended 혼합**이다.
    → **Closed 질의(매출액, 어느 기업이 더 큰가, 해지 계약 존재 여부)에만 self-consistency,
    Open-ended 서술형에는 부적합.** 라우터가 이 분기를 담당해야 한다.
  - 💡 calibration 부재는 "모델이 자기 확신도를 스스로 가늠하지 못한다"는 뜻 →
    **「정보한계 대응」을 LLM 자기평가에 맡기면 안 된다.** 검색 점수 임계 같은 외부 신호를 써야 한다.

## 4. ReAct — Synergizing Reasoning and Acting

- **문제** — CoT는 **정적 블랙박스**다. 내부 표상만으로 사고하니 외부에 접지되지 않아
  사실 환각과 오류 전파가 생긴다. 반대로 행동만 하는 방식은 고수준 목표를 추상적으로 사고하지 못한다.
- **방법** — 행동 공간을 `Â = A ∪ L`로 확장. 언어 공간의 행동 = **thought**(환경에 영향 없음,
  관찰 없음). thought는 목표 분해·계획 수립, 상식 주입, 관찰에서 핵심 추출, 진행 추적,
  **예외 처리 및 계획 수정**에 쓰인다. thought-action-observation을 교차 생성.
  Wikipedia API 3종만 제공: `search[entity]` / `lookup[string]`(Ctrl+F) / `finish[answer]`.
- **결과** (PaLM-540B, HotpotQA EM / Fever Acc)

  | 방법 | HotpotQA | Fever |
  |---|---|---|
  | Standard | 28.7 | 57.1 |
  | CoT | 29.4 | 56.3 |
  | CoT-SC (21 samples) | 33.4 | 60.4 |
  | Act only | 25.7 | 58.9 |
  | ReAct | 27.4 | 60.9 |
  | **CoT-SC → ReAct** | 34.2 | **64.6** |
  | **ReAct → CoT-SC** | **35.1** | 62.0 |

  ALFWorld/WebShop에서는 1~2-shot ReAct가 10³~10⁵건으로 학습한 모방·강화학습을
  절대 성공률 **+34% / +10%** 로 능가.
- **ARGUS 시사점** — **에이전트 루프의 골격이 이 논문이다.** 네 가지가 바로 쓰인다.
  1. **backoff 휴리스틱을 그대로 가져올 수 있다.**
     - `ReAct → CoT-SC`: 주어진 스텝 내 답을 못 내면 폴백
     - `CoT-SC → ReAct`: n개 샘플 중 다수 답이 n/2 미만이면(내부 지식 불확실) 검색으로 전환
     → 이건 **「정보한계 대응」 지표의 구현체**다. 자체 설계할 필요 없이 검증된 규칙이 있다.
  2. **hop 예산의 근거** — HotpotQA 7스텝/Fever 5스텝 이상은 성능이 안 오르고,
     정답 궤적 중 7스텝을 쓴 것은 **0.84%** 뿐이었다.
     → ToG-2 depth ≤ 3 같은 상한이 자의적이지 않다는 근거.
  3. **표에서 읽을 것** — ReAct 단독은 HotpotQA에서 CoT보다 낮다(27.4 vs 29.4).
     **검색을 붙이는 것만으로는 이기지 못한다.** 조합이 이긴다. 과잉 기대 금지.
  4. `search`/`lookup` 2단 구조는 GraphReader의 atomic fact → chunk 하강과 같은 발상이고,
     **공시 목차 → 섹션 → 원문** 하강에 그대로 대응된다.

## 5. Toolformer

- **문제** — LM은 산술·사실 조회처럼 훨씬 작은 모델이 잘하는 일에 취약하다.
  도구를 붙이려면 대량의 인간 주석이 필요하거나 태스크별로 한정됐다.
- **방법** — **자기지도 도구 학습.** ① 프롬프트로 API 호출 후보를 위치별 샘플링
  ② 실제 호출해 결과 획득 ③ **필터링 — API 호출과 결과를 프리픽스로 줬을 때
  다음 토큰 예측 손실이 임계 이상 줄어드는 호출만 남긴다**(`Lᵢ⁻ − Lᵢ⁺ ≥ τf`)
  ④ 그렇게 증강한 데이터로 LM 자체를 파인튜닝. 도구 5종: QA·위키검색·계산기·달력·번역.
- **결과** — GPT-J 6.7B 기반으로 훨씬 큰 GPT-3를 여러 태스크에서 상회.
  핵심 언어모델링 능력(perplexity) 손상 없음.
- **ARGUS 시사점** — **원본 방법은 적용 불가**하다. 파인튜닝이 전제이고 HCX 베이스 모델은
  우리가 학습시킬 수 없다. 하지만 두 가지가 남는다.
  - **"모델이 스스로 언제·무엇을 호출할지 결정한다"** 는 목표는 CLOVA Studio의
    **function calling**으로 달성 *가능*하다 — 학습 없이 같은 효과를 낼 수 있는 경로다.
    🔴 단, **그 경로는 현재 파이프라인에 연결돼 있지 않다** (§7 표 정정 참고).
  - **필터링 기준의 발상이 값지다** — "이 도구 호출이 실제로 예측을 개선했는가"로
    호출의 유용성을 사후 판정한다. 우리 버전으로 옮기면:
    **"이 검색이 답변 품질을 실제로 올렸는가"를 오프라인에서 측정해
    few-shot exemplar와 도구 호출 정책을 고르는 데 쓴다.** GraphRAG-R1의 PRA 보상
    ([../idea/idea.md](../idea/idea.md) §3.9)과 같은 문제를 학습 없이 다루는 방법이다.

## 6. 계보와 ARGUS 매핑

```
GPT-3 (2020)          학습 없이 few-shot으로 태스크를 푼다      → 우리 접근의 전제
   │                  단, 추론 태스크는 약하다
   ▼
CoT (2022)            중간 단계를 예시에 넣으면 추론이 열린다    → think_trace
   │                  단, greedy 한 경로라 취약하고 ~100B 창발
   ├──────────────▶ Self-Consistency (2023)  k경로 다수결        → Closed 질의 정확도
   │                  단, 고정 답변 집합에서만
   ▼
ReAct (2023)          사고를 외부 행동으로 접지 → 환각·오류전파 완화 → 에이전트 루프
   │                  단, 단독으로는 CoT를 못 이김 (조합이 이김)
   ▼
Toolformer (2023)     도구 호출을 모델이 스스로 결정              → function calling
                      단, 파인튜닝 필요 → 우리는 불가
                      🔴 그 발상(function calling)도 A24 로 재고 기각 — 아래 최종 판정
```

**질의 유형별 조합** (평가 질의 6종 → [CONVENTION §6](../../docs/CONVENTION.md))

| 질의 유형 | 예시 | 적용 조합 |
|---|---|---|
| 검색·추출 (Closed) | "2025년 연결기준 매출액은?" | 메타데이터 필터 + 단순 검색. **CoT 불필요** (이득 없음) |
| 검색·추출 (Open) | "주요 투자 계획을 정리해줘" | ReAct + CoT (다수결 부적합) |
| 다중 비교·연산 (Closed) | "A와 B 중 설비투자가 큰 곳?" | ReAct + **Self-Consistency** (고정 답) |
| 다중 비교·연산 (Open) | "자금조달을 유형별로 정리" | ReAct + GoT aggregation |
| 복합 추론 (Closed) | "해지된 계약이 존재하는가?" | ReAct + **Self-Consistency** + 정정공시 체인 |
| 복합 추론 (Open) | "핵심 사업 변화를 설명해줘" | ReAct + 섹션 하강 + 커뮤니티 요약 |

## 7. 제약 정합성

| 방법 | 학습 필요 | HCX API로 가능 | 비용 | 판정 |
|---|---|---|---|---|
| few-shot ICL (GPT-3) | 없음 | ○ | 프롬프트 길이만큼 | **채택 — 전제** |
| CoT | 없음 | ○ | 출력 토큰 증가 | **채택 (단, 창발 여부 실측 필요)** |
| Self-Consistency | 없음 | ○ | **k배** | **채택 (Closed 한정, k 소값)** |
| ReAct | 없음 | ○ | hop당 1~2회 | **채택 — 골격** |
| Toolformer 파인튜닝 | **있음** | ✗ | — | **제외** |

## 🔴 Toolformer 행 정정 (2026-08-15 · `R1-5`)

**종전 서술**(이 표) — *"Toolformer 발상(function calling) → 채택(대체 구현)"*.
**실제 상태** — `tools.TOOL_SPECS`(검색 8종 + 계산 7종 = 15종)는 정의돼 있고 `chat()` 에도
`tools` 인자가 있다(`clova.py:77`, `toolChoice="auto"`). **그런데 생성 호출
`pipeline.answer_question` → `chat(..., max_tokens=…)` 이 그 인자를 넘기지 않는다.**
`src/argus/ablation.py:119-121` 이 스스로 문서화해 뒀다:

> 계산 도구 14종은 `TOOL_SPECS` 로 노출돼 있지만 생성 호출에는 `tools` 를 넘기지 않는다
> (`pipeline.answer_question` → `chat(..., max_tokens=…)`). 따라서 "function calling 을 끈다"
> 는 조작은 실행 경로에서 아무것도 바꾸지 못한다 — Δ 가 정의상 0 이 되는 헛측정이다.

🔴 **"채택(대체 구현)"은 과장이었다.** 실제로 채택된 대체 구현은 `A5`(근거 텍스트에
결정적 계산값을 박아 넣는 것)이지, function calling 자체가 아니다. **왜 애초에 연결하지
않았는지는 코드에 기록이 없다 — 모른다.** 위 주석은 "끄는 조작이 헛측정"이라고만 적었고
"왜 처음부터 안 켰는가"는 설명하지 않는다.

**연결하면 잔여 오답 몇 건을 겨냥하는가 (2026-08-15 · LLM 0회 · `multi_agent` 검토
`33c3d99` 재사용).** 그리드 잔여 오답 6건(`Q-018`·`Q-023`·`Q-044`·`Q-087`·`Q-093`·`Q-097`)
중 **`Q-018`·`Q-044`·`Q-097` 3건**이, 결정적 검사군이 이미 발화하는 5건 집합
(그리드 3 + 밸류체인 `Q-109`·`Q-115`)과 같다. 나머지 `Q-023`(체인 오라벨링)·
`Q-087`(근거 절단)·`Q-093`(영구 오류)은 계산 도구가 닿는 표면이 아니다.

🔴 **그런데 그 3건은 이미 더 싸고 결정적인 대안이 선점했다.** `Q-044`·`Q-097` 은
`A20`(검사 재계산값 치환, 0원 · LLM 0회 · 100% 결정적)이 겨냥하고, `Q-018` 은
`A15`/`A21`(출처 게이트, 0원)이 겨냥한다. `tools=` 를 켜는 것은 **같은 표적을, 모델이
도구를 올바르게 호출한다는 보장 없이, 더 비싸게(~2,060~4,120원, 호출 왕복 +1~2)** 다시
겨냥하는 것이다. **순증 표적 = 0.** 그리고 실제 라이브 호출로 검증된 적이 한 번도 없다
(이 정정 작업도 LLM 0회 원칙 아래 수행돼 새로 검증하지 못했다).

## ❌ Toolformer 최종 판정 — **연결해서 재고 기각** (2026-08-15 · `A24` · 3,759.2원)

위 `R1-5` 는 *"미판정"* 으로 남겼다. **v4 가 실제로 연결해서 쟀다.**
`Arm.function_calling` 을 만들고 `pipeline._answer_with_tools` 로 **왕복**(모델이
`toolCalls` 를 내면 `tools.execute()` 로 실행 → 결과를 `role="tool"` 로 되먹임 →
2회차 호출)을 구현했다. `A24 = A8 + function_calling`.

```
그리드 72     A8 65  ->  A24 59      Δ = −6 (−8.3%p)
전체 88       A8 81  ->  A24 74      Δ = −7
밸류체인 12   A8  6  ->  A24  6      Δ =  0   (+Q-110 / −Q-111 로 갈렸다)
회귀 9건 · 호출 129 -> 165회(+27.9%) · 프롬프트 토큰 +44.0% · 비용 +33.3%
도구 발화 37/88 문항(42.0%) · 47건
```

🔴 **기각 사유는 "모델이 도구를 안 불러서" 가 아니다.** 42.0% 가 불렀다. 사유는 셋이다.

**① 🔴 도구가 정답을 줘도 모델이 옮겨 적지 못한다 — 이것이 결정적이다.**
유일하게 계산 도구가 닿는 겨냥 `Q-044` 에서 `calc_total` 이 **골든과 바이트까지 같은
`2,365,868`** 을 돌려줬는데, 답변은 **`2,366,968`** 을 썼다. 같은 인자로 돌린 독립
스모크에서는 `2,366,868` 이 나왔다 — **두 번 다 틀렸고 틀린 자리가 다르다.**
Toolformer 의 전제는 *"LM 은 산술에 약하니 도구에 넘기자"* 인데, **우리 도메인의 병목은
산술이 아니라 전사(轉寫)** 다(`Q-018` 13자리 전사 오류 · `A18` LLM 추출 환각률 62.1% 와
같은 기전). 도구는 그 축을 건드리지 않는다.

🔴 **그리고 이것이 `A20`(재계산값 치환)이 이기는 이유를 설명한다** — 치환은 값을
코드가 문자열에 박으므로 **옮겨 적는 단계가 아예 없다.** 같은 표적, 같은 값, 0원,
전사 오류 0%.

**② 모델이 부른 도구의 과반이 계산이 아니라 검색이다.** 전체 88 에서 47건 중
**검색 26 · 계산 21** (`read_section` 16 · `get_history` 10).
근거는 이미 프롬프트에 실려 있는데 모델이 다시 읽으러 가고 그 결과가 근거를 희석한다 —
회귀 8건 중 **7건이 도구를 불렀다.** G-Retriever 가 실측한 *"걸러지지 않은 컨텍스트가
frozen LLM 을 악화시킨다"* 와 같은 현상이다.

**③ `tools` 와 `maxTokens` 가 배타다**(40001 · [CONVENTION](../../docs/CONVENTION.md)).
도구를 내미는 회차는 길이 상한을 못 건다. 도구를 **한 번도 안 부른** `Q-106` 도 회귀한
것이 그 몫이다.
